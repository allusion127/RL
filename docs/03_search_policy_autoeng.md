## 1. 탐색 루프 전체 구조

`lpopt optimize`(`lpopt/search/campaign.py::run_campaign`)의 웨이브 1회:

```
① 후보 풀 구성 (construct.build_pool)              pool_size 20,000
② 서로게이트 채점 + 신뢰영역 게이트 (acquisition)
③ 상위 후보 국소탐색 (local_search)                top_m 256 · neighbors 200 · depth 3
④ 8슬롯 웨이브 구성 (compose_wave)                 exploit 5 / explore 2 / control 1
⑤ MASTER 실계산 (verify.WaveVerifier)              multi_pc 병렬 · 3분류 회계
⑥ 스토어 append + 원장 + 엘리트 아카이브
⑦ 온라인 미세조정 + 2패널 게이트 (update.WaveUpdater)
⑧ 웨이브 리포트 + 체크포인트 (state.json / labels.jsonl)
⑨ 정지규칙 (min_waves_before_stop 6 · no_improve_waves 3)
```

### 1.1 후보 생성 — 게놈과 구성기

**게놈**(`lpopt/search/genome.py`, `GeneralOrbitGenome`) — 벤더 `OrbitGenome`의 feed 121
깊이-1 완전매칭을 **깊이-2 소스체인**으로 확장해 `1 + 4N` 격자의 임의 feed를 표현한다.
구조 불변식: 60 가동 오빗 유닛이 `N` fresh / `60−N` burned로 갈리고 중앙 슬롯은 **항상 fresh이며
소스가 되지 않는다**; 소스 그래프는 **비순환 in-forest**, 깊이 ≤ `max_shuffle_depth`(기본 2);
strict 모드에서 `feed = 1 + 4N`, `depth-2 간선 = 60 − 2N`(N ≤ 30). N > 30이면 `2N − 60`개
fresh가 단주기 방출되며 `allow_single_cycle_discharge` 뒤에 갇혀 있다(f125→N=31, f129→N=32 자동).

- **대칭**: 노심 **1/4 대칭**(69 quarter slot, 다중도 w ∈ {1,2,4}, Σ = 241), 집합체 **1/8 대칭**.
  2026-07-23 확정 설계규칙 — **R1** 패턴 내 전 feed 동일 농축 사양, **R2** 집합체 1/8 대칭,
  **R3** 노심 1/4 대칭.
- **신연료 알파벳 확장(2026-08-17)**: `case_batches()`가 `A_B` / `A_B_C` / … 최대
  `MAX_FRESH_TYPES = 5`를 파싱. 2종 경로는 **바이트 동일**(이동열 sha256 `76a4149a…` 불변),
  3종 경로도 5종 확장 후 sha `a40d6886…`로 고정.
- **연산자**: `rewire_swap`(연소 유닛 2개 소스 교환), `fresh_relocate`, `batch_flip`,
  `batch_swap`, `add/remove_fresh_unit`(셀 내부 금지 — `feed_move_prob = 0.0`),
  `graded_morph`(2종 엘리트 → 3종 cold-start: 반경 극단 슬라이스를 최소 종으로 재라벨,
  feed·배선·depth-2 수 보존). 300회 재생 실험에서 단일 이동 6종 분류 정확도 **100%**.

**후보 풀**(`construct.build_pool`) 3소스 — **엘리트 변이 ~60%**(부모 = 스토어 최상위 검증행,
셀이 비면 **feed-morph**한 인접 feed 엘리트, 직전 웨이브 `prev_top`; 자식은 `n_moves_early 2` →
`n_moves_late 5`), **롤아웃 채점 유도구성 ~30%**(시드 prefix를 `completions_per_prefix = 8`개
**완전** 패턴으로 완성 → CNN이 완전 보드만 채점 → beam 4 상위), **다양성 ~10%**(ring/checker/
radial + 균일 무작위). 모든 후보가 `origin`·`parent_record_id`·`record_id`를 싣고 중복 제거된다.

feed-morph 비용은 작다 — 옥탄트 게놈에서 121 → 113은 **2 유닛 편집**(125 → 113은 3).
`fpcamp_minfr_N1N2_f113`에서 32개 엘리트 부모 전부가 깨끗하게 morph됐다.

### 1.2 획득함수 — UCB/LCB, 목적 LCB + 마진 타이브레이크

핵심 설계는 **M5 파일럿의 버그 교훈**에서 나왔다 — exploit 슬롯을 탐험가중이 붙은 `acq`로
랭킹하면 **raw σ 항 때문에 고-σ OOD 후보가 모든 슬롯을 가져간다**.

| 구성요소 | 정의 | 역할 |
|---|---|---|
| `p_feasible` | `Π Φ((limit − μ_c)/σ_total,c) × P(수렴)` — F_r/CBC/F_q/\|AO\| | τ 게이트 |
| `feasibility_margin` | 축별 위험조정 초과 `(μ + κσ − limit)/width`의 **최악값의 음수**(κ = `risk_z` = 0.25) | **타이브레이크 키** |
| `rank_with_tiebreak` | exploit을 `tie_epsilon` 버킷으로 양자화, 버킷 내부는 margin 분위순위 | 경계 분지 축퇴 해소 |
| `raw_epistemic` | 예측 5축 앙상블 epistemic σ 최댓값 | **explore 슬롯 전용** |
| `tau_schedule` | feasible 라벨 전 `tau0 = 0.30`, 이후 in-region `p_feas` **75분위**(상한 0.95) | 게이트 적응 |

목적별 exploit 스칼라(전부 보수적 방향의 LCB/UCB):
- `min_fr_max_cycle`: `cyclen_LCB − λ_Fr·F_r_UCB`(기본 λ_Fr = 1000 ⇒ ΔF_r 0.01 ≡ 10 EFPD),
  F_r/F_q/CBC/\|AO\|/예측 핀BU **5축 계층 하드 게이트**(위반 시 `TIER = 1e4` 페널티).
- `max_cycle_min_fr`: 같은 스칼라, **F_r은 게이트가 아니라 최소화 대상**.
- `fr_boundary`: `−(μ_Fr + κσ_Fr)`, F_r은 **순수 목적** + 중간티어 밴드 셰이핑
  (`band_lo 1.45`/`band_hi 1.70` 밖의 예측 F_r **평균** 강등 → OOD-저 F_r 모드붕괴 방지).
  cyclen 필드 자체가 없어 주기길이가 랭킹에 새지 않는다.
- `flat_power`: `−(z_peak + w_cov·z_cov)`, `z = UCB/scale`. **node_peak이 PRIMARY**
  (셀내 ρ(node_peak, F_r) = 0.983, map_cov의 partial ρ는 0.107뿐). **F_r은 목적이 아니라
  안전 게이트 1.70**이며 셀별 편향보정은 `1.70 − bias − 0.5σ`로 **조이기만** 한다(초안의 1.75 기각).
- `user_criteria`(§12.5): 밴드 축 2개(목표 cyclen ± tol, 목표 방출연소도 ± tol) + 밴드내
  **F_r UCB 최소화**. F_r은 이중 역할(선택적 게이트 + 목적). **MTC/SDM은 절대 채점되지 않고**
  후검증으로 넘어간다.
- `min_fuel_cost`: 신연료 U-235 장입량 `FE`가 위치 불변 → 셀 단위로 정확 → 외곽 레이스가
  FE 오름차순 소거 토너먼트가 된다.

**엔지니어링 규칙 소프트 페널티**: `flat_power`에 한해 `rule_penalty_weights`로 검증된 배열
통계량(rm1/rm1i/rm2/rm2i)을 exploit `total`에서 뺀다(기본 0.0 → 바이트 동일).
**하드 컷이 아니라 ~0.02 오더 소프트 페널티**가 캠페인에서 실증된 소비 형태다.

### 1.3 신뢰영역과 OOD 가드

`TrustRegion` — `(feed, e_core-bin)` 지지격자 게이트. `e_core_band = 0.10` binning,
스토어에서 **`n_min = 50`행 이상**인 bin만 supported, 캠페인 자기 셀은 항상 in-region.
밖이면 **하드 제로**(exploit −inf), `feed_step = 4`(1+4N 한 걸음) 또는 e_core 1밴드 이내면
**frontier**로 보고 σ를 `frontier_sigma_inflation = 1.5`배 부풀린다. 검증 라벨마다 `observe()`가
카운트를 올려 `promote_after = 16`에서 승격 — **측정된 라벨로만 영역이 자란다.**

추가 가드: `screen_e_core_band(tol = 0.02)`(배치 flip이 50/50 분할을 흔드므로) ·
`compose_wave(exploit_verified_hamming)`(exploit 픽은 **모든 검증 패턴과 Hamming ≥ 임계**를
완화 폴백에서도 강제 — 서로게이트가 구별 못 하는 근사 중복이 예산을 먹는 것 차단) ·
후보 간 `hamming_min = 4` · 핀연소도 예측 게이트 `minfr_pin_bu_limit = 78.0`
(= 인허가 80 − **모델오차 여유 2.0**; 근거: s1g 핀헤드의 E1_E2/f109 셀내 검증 n=33,
MAE 1.84, bias **−1.39**(과소예측)).

### 1.4 웨이브 MASTER 실계산 (verify)

`lpopt/search/verify.py::WaveVerifier` — 스냅샷 GA 평가기의 충실한 이식.

- **병렬**: 벤더 `ParallelPatternEvaluator`(P-코어가 물리 소유, 호스트는 E-코어로 후퇴).
  함대 다중 PC는 **PC당 다중 인스턴스 + 서로소 로스터 + 시드 분리**로 8슬롯 한계 우회.
- **이종 케이스 혼합**: produce 웨이브는 엔트리별 `CaseData`를 만들어 워커에 개별 배급.
- **재시작 참조 재작성**: fallback level ≥ 1이면 `prepare_cycle1_deck`이 스테이징 전 재작성.
- **자산 사다리**: 0 `native` → 1 `promoted`(셀 자체 수렴 재시작 캐시) → 2 `pair_feed` →
  3 `pair_ecore` → 4 neutral. 71,517행에서 tolerance_margin 중앙값이 level 0/2/3에서
  0.30 / 0.20 / 0.17로 **동일 분포**이고 **폴백 시드가 오히려 더 적은 주기로 수렴**
  (11.2 → 9.8 → 9.3). 교차-feed 폴백의 고정점 동일성은 A/B로 직접 측정 —
  |Δcyclen| **0.007 EFPD** / |ΔF_r| **0.000000** / |Δcbc| **0.00 ppm**(허용치 0.8 / 2e-3 / 2).
- **3분류 정직회계**: `converged` / `nonconverged` / `error`. `error`는 다시
  **물리 킬**(`non_finite_flux` — `(패턴, restart)` 쌍의 정직한 음성 속성; 절대 스트라텀을
  중단시키지 않는다)과 **하네스 오류**(스테이징/덱/리졸버/타임아웃)로 갈린다.
- **결정론**: batchswap 웨이브의 중복 7쌍이 독립 실행돼 **7/7 F_r 비트 동일**; fr_arms A0
  독립 복제 스프레드 **0.0000**. → **0.001 수준 F_r 차이도 실신호.**
- **purge 가드**: `purge_case_dirs = true`가 웨이브마다 작업 트리를 지우므로 `promote()`는
  반드시 `_maybe_purge()` **이전**. `cases_dir` 보호 가드가 캠페인 디렉터리 오삭제를 막는다.
- **수렴 조건**: `max_cycles 16`, `consecutive 2`(5-FOM 연속 비교), `timeout 3600`.
- **캐시**: `record_id = sha256(정규 패턴 | library_id | case_pair | …)` → 동일 패턴은 재계산 없이
  회수(`PRODUCE_DECK_KNOBS = "ga80_produce"` 서명 공유).

수렴률 실측: 생산 경로 **0.61–1.00**(군집 0.75–0.80) → `N` 라벨에 `1.33 N` 체인 계획.
최적화 캠페인의 morph-엘리트 영역은 훨씬 얌전하다 — f113 **98/100(98.0%)** vs 셀 이력 68.4%.

### 1.5 스토어 갱신 · 온라인 게이트 · 증분 재학습

**웨이브 온라인 게이트**(`update.WaveUpdater`) — 신규 8라벨 + 리플레이(`replay_size = 512`)로
로컬 CPU 미세조정(`finetune_epochs = 3`) → **challenger**, **2패널 합의**에서만 교체:
① 동결 (feed, e_core) 층화 홀드아웃 **셀내 Spearman**(feasible 클러스터가 극도로 좁아 절대

### 2.1 `min_fxy` — 새 목적축이 탐색층에 들어온 방식

**결정 (사용자, 2026-08-29, 구속력):** 목적 = **`min(max F_xy)`**, 한계 **1.65**, `F_r`은 제약.

축을 바꾼 이유는 물리다. `F_xy`(핀 평면 첨두)는 `F_r`(집합체 반경 첨두)보다 상위이고
`F_r ≤ F_xy ≤ F_q`가 실측 192/192에서 성립하지만, **게이트는 서로 대체되지 않는다** —
`E1_E2/f109`에서 `F_r ≤ 1.55` 통과 52개 중 **18개가 `F_xy ≤ 1.65`에서 탈락**한다. 그래서
`min_fxy`에서 `f_xy`는 **목적이자 경성 한계**이고 `f_r_limit`은 1.55로 **남는다**.

**`MinFxySpec`** — `lam_fxy = 1000.0`, `risk_z = 0.25`, `f_xy_limit = 1.65`,
`f_r_limit = 1.55`, `cbc 1600`, `f_q 2.41`, `ao_abs 0.30`, `minfxy_pin_bu_limit = 78.0`.
`score_min_fxy`는 `cyclen_LCB − λ·F_xy_UCB`이고 `F_xy_UCB = mean + risk_z·std`이며,
**`fxy_std`가 NaN이면 `constraint_ok = False`** 다. 서빙은 동결 7열 계약을 건드리지 않고
`PosValCnnBackend.predict_fxy`라는 **별도 경로**를 쓴다(`predict_map_flatness`의 선례).
`p_feasible`은 여전히 F_r/CBC/F_q/\|AO\| 4축만 곱한다.

**`flat_power`에도 `F_xy` 안전게이트가 붙었다.** `node_peak`은 `F_xy`가 **아니므로**
(상관 0.74–0.85) 평탄한 패턴이라는 이유로 `F_xy`를 보증할 수 없다 →
`flatpower_fxy_limit`(0 또는 비유한 값이면 비활성).

### 2.2 두 개의 실현가능성 술어 — `is_feasible_search` / `is_deliverable`

외부 검토 §6.4(P0-03)는 "**결측 핀연소도를 feasibility PASS로 처리** → `unknown = safe`"를
P0 결함으로 지적했다. 하나였던 술어가 둘로 갈라졌다.

| 술어 | 결측 축 처리 | 소비자 |
|---|---|---|
| `is_feasible_search` | `max_pin_burnup`·`f_xy`는 **통과**, 나머지 게이트 축은 **거부** | 랭킹·엘리트·best-tracking·`n_feasible`·리포트 |
| `is_deliverable` | **전부 거부** — 모든 게이트 축이 **측정**되어 있어야 하고 `unknown_axes`가 무엇이 없는지 이름을 댄다 | 납품 판정·`delivery.json` |

관대한 쪽은 **탐색이 굶지 않게** 한다: 목적축이 바뀐 순간 스토어의 98.2%에 `F_xy` 라벨이
없었으므로 엄격한 거부였다면 첫 `min_fxy` 캠페인은 시작조차 못 했다. 엄격한 쪽은
**측정되지 않은 인허가 축을 만족했다고 부르지 않는다**. `min_fxy` r1의 95행은
`unknown_axes = ["max_pin_burnup"]`이 **95/95**였고 `deliverable`은 **0**이었다 —
그래서 핀 웨이브(phase-2)가 라운드의 구조적 후속 단계로 등록되어 있었다.

### 2.3 안전 실드 — OOD 정책과 conformal 게이트 (Phase A-2, 2026-08-29)

검토 §6.5(P0-04)는 "OOD 가드와 conformal 구간이 **계산·인쇄된 뒤 무시된다**"고 지적했다.
`ood_guard.py` / `conformal.py`는 **한 줄도 바뀌지 않았고**, 두 신호가 인수·풀·납품 도시에
연결됐다.

| 노브 | 기본값 | 값 |
|---|---|---|
| `ood_policy` | **`warn`** | `warn` 경고만 / `escalate` `exploit`·`rank`를 `−inf`로(→ explore·control 티어만) / `reject` 풀에서 제거 |
| `conformal_gate` | **`false`** | `true`면 split-conformal 상한이 `U_c(x) ≤ L_c` 경성 스크린 |
| `conformal_alpha` | **0.10** | `conformal.DEFAULT_ALPHAS` = {0.10, 0.32} — 적합되지 않은 α는 **덱 로드 시점에 거절**(공허한 `+inf` 구간을 조용히 쓰는 대신) |

- **적용 순서는 OOD 먼저, conformal 나중.** off-manifold 후보의 구간은 그 manifold 위에서
  교정된 것이라 애초에 bound가 아니기 때문이다.
- **가드 상태 3분류**: `absent`(백엔드에 가드 없음 → `ood_flag = None`, `False`가 **아니다**) /
  `available` 정상 → bool / `available` 예외 → **fail-closed**(플래그 처리 + 오류 계수).
- **게이트 축** = `f_r`·`cbc_max`·`f_q`·`ao_abs`. `max_pin_burnup`은 78 vs 80 모델 마진과
  **이중 계상**이라 의도적으로 제외했고, `cyclen`은 양단 밴드라 단측 상한과 맞지 않아 제외했다.
- **`F_xy`는 아직 conformal 밖**이다(7열 계약 밖) — `fxy_conformal_upper`는 `f_xy` 헤드와
  `conformal.json`의 `per_target["f_xy"]`가 **둘 다** 있어야 bound를 만들고, 아니면 프록시 σ
  스크린을 유지하며 웨이브 리포트에 `conformal_fxy: "proxy"`로 남는다.
- **기본값에서는 실드가 실행조차 되지 않아 웨이브 구성이 바이트 동일**하다 —
  `tests/test_safety_shield.py` 29건이 그것을 단언한다.
- 미해결: `CONFORMAL_TARGETS`에 `f_xy`가 없고, **OOD가 실제로 발화하는 셀이 없다**
  (현 학습 개체군에서 geometry 채널이 상수). 전향 검증 arm A0–A4는 설계만 되어 있다.

### 4.3 규칙 간 상충 — 측정된 트레이드

**(a) 평탄도 vs F_r은 가능영역 안에서 역상관**(최평탄 코어 위 13점 dose에서
Pearson(F_r, node_peak) = **−0.750**). 같은 레버가 부호를 바꾼다 — `fresh-on-crest`(R6)는
node_peak −0.680 / f_r +0.508.

  얕은 셀에서는 두 목적이 아직 동행한다.

### 4.4 실증(acid test) — FAILURE, 그리고 그것이 규칙의 정당한 위치를 정했다

| 프로파일 | 규칙제 최고(실측) | 사전등록 기준 | 탐색 기록 |
|---|---|---|---|

**판정 FAILURE.** 그러나 정직한 해석은 두 갈래다.

② **규칙이 못 잡은 것 — 마지막 ~0.1.** 잔차는 26규칙의 선형결합이 아니라 미세 배열 상호작용에

가드는 `n_unit_edits`이고 클래스별 상한이 뚜렷하다(`batch_flip` 1, `rewire_swap`/`batch_swap` 2,
`fresh_relocate` 4) → `single_move` 불리언으로 걸러 쓴다.

**물리 주석**: 반경 3분위(r<5.0 / 5.0≤r<7.0711 / r≥7.0711 = 69/80/92 집합체)로
`fresh_share_inner/middle/periph`, `fresh_r_center`, **`fresh_enr_r_center`**(농축도 가중 —

소스체인 리졸버로 **정확히** 계산되며 연소도에서 추정하지 않는다. 반응도 가중이 `kinf0`가 아니라

NaN이라 **코퍼스가 가장 조밀한 곳에서 조용히 결측**되기 때문.

**계보의 구조적 한계**: 가장 깊은 체인 79간선, 가장 깊은 **F_r 개선 연속 체인은 7**.

→ "다음에 어떤 한 수를 둘지"는 배우지만 **다단 credit assignment는 공짜로 안 온다.**

Spearman: **v2 +0.605 / v1 +0.344**.
**v2의 최대 미스**는 `rewire_swap`/neutral(실측 개선률 0.446, 점수 0.060)인데 이것은 **설계된 것**
이다 — 이득 크기가 압도적으로 작아(최대 `d_f_r` −0.0079) 크기 가중 목표가 의도적으로 낮게
랭크하고, 그것이 `improved_*` 기반 precision@32를 깎아 2절 FAIL에 기여한다.

### 5.4 캠페인 배선 — `policy_prior` 플래그와 조용한 실패

`construct.build_pool`에 **이미 배선돼 있다**: `_policy_prior(cfg)`가
`[acquisition] policy_prior != "off"`일 때 `MoveScorer`를 로드하고, 채점된 엘리트 슬롯이
**한 부모에서** `policy_prior_candidates = 16`개 편집을 제안하면 `_policy_pick`이
**softmax 샘플링**한다. `policy_prior_random_floor = 0.20`은 채점되지 않은 채 남는다.
`tests/test_policy_prior.py`가 플래그-off 바이트 결정성·원장·바닥·조용한 성능저하를 지킨다.
**기본값 `off`.**

**레일**(정책 결과 문서 §7/§8): argmax가 아니라 **온도 softmax** · 채점되지 않은 무작위 변이의
**바닥 유지** · **고정 부모 안에서만** 채점 · **이 보고서가 아니라 A/B로 게이트**
(짝지은 웨이브 prior on/off, **MASTER 콜당 발견 엘리트 수**).

**v2 투입의 두 관문, 하나는 조용히 실패한다**:
1. 덱 2줄 — `("acquisition","policy_prior") = "fr"`,
   `("acquisition","policy_prior_model_dir") = "data/models/policy_v2"`.
2. **`lpopt/policy/scorer.py`는 실제 변경이 필요하고 건너뛰면 SILENT로 실패한다.**
   `MoveScorer.score`가 v1의 `scalar_features`(36열)를 쓰는데 v2 체크포인트 `meta.json`은 39열을
   선언한다. 불일치는 `score()` 안에서 예외를 던지고 `_policy_pick`이 **설계상 모든 예외를 삼키므로**
   결과는 **매 확장마다 균일 무작위 추출** — 즉 **처리군이 곧 자기 대조군인 A/B**가 된다.
   수정은 `meta["policy_version"] == "v2"` 분기로 `scalar_features_v2` 호출 + `move_frame`에
   `era_current` 추가.
3. **`policy_prior_temperature`는 상속하지 말고 재유도.** v1 출력은 확률이고 스프레드 **0.573**이라
   τ = 0.25가 ~10배 승산비를 남겼다. v2 출력은 정규화·클립된 기대개선으로 스프레드가
   **0.189(fr)/0.144(flat)** — 같은 승산비에 **τ = 0.082/0.062**가 필요하다. 0.25로 두면
   softmax가 거의 균일해 prior가 아무것도 안 한다.

**첫 A/B로 권고된 것은 OPEN 배선이 아니라 PROBE 대체**다. autoeng의 PROBE는 **부모 없이**
8보드를 처음부터 짓는데 무브 정책에는 맞지 않는 소비처다. 대신 ① 이웃 셀 최근접 엘리트 1개를
앵커로 feed-morph, ② N ≈ 64 단일이동을 v2로 채점, ③ 위 τ의 softmax 상위 8에 8콜, ④ 1개는
채점 없이 남겨 blind 전이를 계속 측정. **이것이 regret@8을 실제로 실행하는 것**이고 개입 게이트
부모 기준 프로브당 **F_r 0.0225**(v1 대비)의 가치가 있다. 비용 ≈ **1.5초** vs MASTER 8체인 ≈ 2,400초.

### 5.5 코퍼스가 고갈됐다 — 다음 증분은 수확이 아니라 측정이다

1. **OPEN 캠페인은 MASTER 콜당 코퍼스 원천으로서 나쁘다** — f113 100레코드 중 96개가

2. **현행 시대 코퍼스는 이미 소진됐다** — `records.parquet`에서 도달 가능한 현행-시대 계보 간선

→ **다음 증분은 harvest가 아니라 measure다.** 처방: 셀당 top ~50 엘리트에서 `n_moves = 1`로
각 이동 클래스를 **전수·방향 층화** 실행. 이것만이 이동 클래스와 반경 방향의 교락을 풀 수 있고,
실제로 그 웨이브가 §4.5의 누설 판정과 §5.2의 v1 낙제 진단을 냈다.

### 5.7 정책 v2 **서빙** — 배선은 끝났고 A/B는 사전등록 초안이다 (2026-08-29)

외부 검토가 **P0-01**로 꼽은 결함: *"최신 정책이 운영 경로의 주 의사결정기가 아니다 —
v2는 평가 코드는 있으나 서빙 경로가 v1 전용이고 `policy_prior` 기본값도 `off`"*.
이 라운드에서 **배선은 닫혔고 실험은 아직 발사되지 않았다**. 두 사실을 같은 크기로 적는다.

**닫힌 것.** `MoveScorerV2`(`policy/scorer.py`), `policy_prior ∈ off | fr | flat | both |
v1 | v2 | shadow_v2`, `policy_prior_strict`(로딩 실패 시 **조용한 random 폴백 금지** —
검토 P1-05), 그리고 `selection.json`에 `policy_mode` / `policy_version` /
`policy_fallback` / `policy_shadow_scores` 기록.

**사전등록 초안** `policy_v2_serving_ab_prereg_20260829_DRAFT.md` — `_DRAFT`가 붙어 있는
동안 **등록되지 않은 문서**다. 실행 조건 2개(① `f_xy` 헤드 ship + 웨이브가
`fxy_source = "head"` 기록, ② 사용자의 MASTER 예산 승인) 중 ①은 `s1j`로 충족됐고 ②는
미결이다.

| Arm | `policy_prior` | 역할 | temperature |
|---|---|---|---|
| **A** (대조) | `off` | 현행 출하 상태 | — |
| **B** | `v1` | 등록된 baseline — **질 것으로 기대**(parent-blocked AUC 0.492 = 우연) | 0.25 |
| **C** | `v2` | 처리군 | **0.08** |

**τ를 공유하지 않는 이유가 설계의 핵심이다.** v1 출력은 확률(게이트 fold p90−p10 spread
**0.573**)이고 v2는 정규화·클리핑된 기대이득(spread **0.189**)이다. 0.25를 그대로 쓰면 v2
softmax가 거의 균일해져 **arm C가 arm A의 사본**이 된다. 0.08이 v1의 ~10배 sampling-odds
비를 v2 스케일에서 재현한다.

**Stage 0 `shadow_v2`(MASTER 콜 0)** 가 권장 첫 단계다 — 풀을 `off`와 **정확히 동일하게**
구성하고(동일 rng·후보·순서, `tests/test_construct.py`가 단언) v2는 점수만
`policy_shadow_scores`에 기록한다. 답하는 것: ① v2 점수가 실현 Δ목적과 연관되는가,
② live 부모의 실현 spread로 τ를 **등록 전에** 재유도할 수 있는가.

**지표는 AUC가 아니다.** P1 = 고정 콜수(32/64/full)에서 **deliverable 노심의 최소 측정
`F_xy`**, P2 = first-feasible 콜. ADOPT는 **3시드 전부** P1에서 A를 이길 때만이고, 2/3이면
"제안용으로만 채택", 미만이면 **서빙 arm 은퇴**(배선은 유지, 기본값 `off`, null로 발표 =
"성능은 서로게이트 인수에서 온다"). 비용은 3 arm × 3 시드 × 64 = **576 MASTER 콜**이며
이것이 유일한 미결이다.

**발사 전에 결함 하나가 이미 잡혔다 (Addendum).** `MoveScorer._board`도 §5.4의
`library_provenance` 유물을 쓰고 있었다 — 코퍼스 census상 **paramA 2,401행이
`g_dataset_flag = 1.0`으로 학습되고 서빙에서는 0.0**으로 들어갔다(13개 조건화 전역 중 1개
반전). 수정은 단일 정의 `policy/data.py::corpus_provenance(library_id)`이며, 측정 효과는
max \|ΔP(improve)\| **paramA 0.087 → 2.2e-04**(ga80은 무영향). **기존 패리티 테스트가 놓친
이유**: 게이트 fold의 행 0–3이 **전부 ga80**이었다. `sym_class`는 일부러 `library_provenance`
값을 유지한다 — 코퍼스가 실제로 그 값으로 빌드됐으므로 train/serve가 **일관되게** 틀린 편이
낫고, 바꾸면 `policy_v2` 체크포인트가 무효가 된다. 코퍼스 재채굴은 **v3의 블로킹 항목**으로
등록됐다.

### 6.1 상태기계

`(pair, feed, library)` 목표 셀마다 **사람이 2026-08-16에 N1_N2/f113에서 손으로 돌린 그 순서 그대로**:

```
0 PRECHECK → 1 PROBE → 2 OPEN → 3 HARVEST+MERGE → 4 RETRAIN+GATE → 5 MAP UPDATE → 6 NEXT CELL
```

**새로운 알고리즘은 하나도 없다.** 드라이버가 새로 기여하는 것은 정확히 셋 —
**사전등록 자동화 / 추가 전용 상태 로그 / 설정 게이트**.

| 단계 | 조합한 코드 | 증명된 선례 |
|---|---|---|
| 0 PRECHECK | `resolver.build_case_resolver` + 사다리 dry-run, `records.parquet`, `dbx_frontier_table.csv`, `cell_verdicts.csv` | f113 덱 헤더의 "THE MARKS" 블록 |
| 1 PROBE | `CurriculumDriver._phase_blind_probe` | `data/curriculum/cells/*/blind_probe.json`(36셀) |
| 2 OPEN | `lpopt optimize`, 노브는 `fpcamp_minfr_N1N2_f113_199.inp`에서 **그대로 승계** | 100콜에 41 feasible, 첫 feasible 23콜 |
| 3 HARVEST+MERGE | `lpopt merge-store` + 백업 규율 | "100 new / 0 upgraded / 0 conflicts" |
| 4 RETRAIN+GATE | `build_split_S1b.py` → `lpopt.remote push/train/status/pull` → `lpopt gate-promote` | 라운드 1–11, 8연속 승격 |
| 5 MAP UPDATE | `scoping_mesh.py` → `mesh_vs_db.py` → `--figure-only` | 그물망 README |
| 6 ORDER | DB 프런티어 스크린 + 전이 측정 | 이웃 feed 이득의 **82–86%가 모델 기여** |

셀당 **30스텝 · 108 MASTER 콜**(프로브 8 + 개방 100), 전 실행 상한 `master_budget_total = 500`.

평균 이동이 **−0.0036**이고 55셀 중 **52셀이 비트 동일**이었다 — **노브가 아니라 측정된 의존관계.**
그리고 `mesh_recompute`가 `mesh_verdict`보다 **먼저** 온다 — `gap_total`은 디스크의

**"전이 없음"이라는 정반대 판독**이 나온다. 그 순서가 코드에 박혀 있다.

### 6.2 사전등록 자동화 — 자동화가 가장 먼저 잃어버릴 것

`prereg` 스텝은 **MASTER 콜이 하나라도 나가기 전에** ① 스토어의 이 셀 바닥(행수/수렴/제약만족,
F_r 하한·p10, cyclen 범위, 과거 수렴률 → 기대 라벨수, 신뢰영역 지지량), ② DB 진실값,
③ 모델 자신의 예측 하한(`mesh_min_pred_f_r`, `f_r_bias_tail`, `corrected_floor`,
`gap_total/data/pool/search` 분해와 판정), ④ 엘리트 부모 집합, ⑤ **성공 기준 PRIMARY/SECONDARY/
PARTIAL/NULL**(NULL 분기까지), ⑥ 등록 유의사항, ⑦ 자산 해석 예측을 덱 헤더에 못 박는다.
**그리고 덱의 sha256이 발사 스크립트의 게이트 값이 된다** — 헤더를 손대면 런처가 발사를 거부한다.
**사전등록이 문서가 아니라 강제 장치가 되는 지점.**

검증된 산출(N1_N2/f109, 전부 측정값):

```
1. 우리 스토어      166행 / 122수렴 / 0 제약만족,  F_r 하한 1.6940,  cyclen 596.9–632.3
                   과거 수렴률 73.5% → 100콜에서 ~73 유효 라벨,  신뢰영역 지지량 166
2. DB 진실값        41 코어,  F_r min 1.5420 @ 648.0 EFPD,  split 0.514 (56×53) → 데이터 갭 +0.1520
3. 모델 예측 하한   1.5780 (feasible 0),  bias_tail +0.0168,  보정 하한 1.5612
                   gap_total +0.0400 / data +0.1560 / pool +0.0232 / search −0.1328 → pool-starved
4. 엘리트 부모      67행 (f113 41, f121 14, f125 12),  최상 부모 F_r 1.4932
등록 유의사항       DB 핀연소도 절벽 — 이 셀 DB 코어 100%가 노드 75 GWd/tU 초과
자산                level 2  pair_feed:MAS_RST.APRQ_11_0677.23   (f113과 동일한 사다리)
```

(`records.parquet` `dffd4d99…`, `maps.npz` `a88cb4a5…`) — **사람의 규율을 기계가 재현한다는 증거.**

### 6.3 인간 게이트 · 함대 가드 · 상태 원장

v1 기본값 `pause_for_approval = ["new_assembly", "retrain_promote_fail", "budget_exceeded"]`,
**그 외 전부 자율.** 원칙 하나 — **되돌릴 수 없거나, 비싸거나, 사람이 기준을 바꾸고 싶어질
지점에서만 멈춘다.** `new_assembly`는 DeCART2D 체인이 비싸고 사람 판단이 여러 번 필요해서
**사전점검까지만 하고 멈춘다**; `retrain_promote_fail`은 FAIL이 *결과*지 오류가 아니고
**자동화가 기준을 완화하는 길은 없다**(등록 폴백은 "현 챔피언 유지 + 플래그");
`budget_exceeded`는 다음 셀 예산을 조용히 당겨쓰지 않기 위함.
멈추지 **않는** 것도 의도적 — 자산 해석 실패·병합 충돌·rc≠0은 승인 요청이 아니라 **버그 신호**라
실패로 기록하고 셀을 중단한다. 게이트 시 `gate_pause` 이벤트 + 종료 코드 10, `--resume`으로 재개.

| 호스트 | 용도 |
|---|---|
| `HOST_199` | 캠페인 · 프로브 · 모델 전용 메시 스윕 |
| `HOST_238` | 학습만(`lpopt_gpu1.inp`로 GPU 1 고정) |
| `HOST_181` | **절대 사용 금지** |

가드 두 겹: ① `load_autoeng_config`가 금지 박스를 가리키면 **로드 자체를 거부**,
② `guard_argv`가 **실행 직전 모든 argv를 검사**(테스트가 30스텝 전부의 `argv`/`poll_argv` 통과).
발사 스크립트는 f113 런처가 증명한 세 게이트 — **busy**(쌓지 않고 거부) · **덱 해시** ·
**사전조건**(챔피언·스토어 존재). 발사는 `Invoke-CimMethod Win32_Process Create`
(이 함대에서 `schtasks`는 조용히 no-op).

`data/autoeng/<run_id>/state.jsonl` — **한 줄 하나의 JSON, 추가 전용, 절대 재작성 없음.**
`kill -9` 비용은 **최대 한 스텝**이고, 마지막 줄이 깨져 있으면 마지막 정상 줄까지 파일을 잘라낸다
(이 복구가 없으면 다음 추가 쓰기가 깨진 줄에 이어붙어 살아남은 기록까지 망가진다;
회귀테스트 `test_state_log_is_append_only_and_survives_a_torn_tail`). `master_calls`가
`step_done` 페이로드에 실려 **원장이 크래시를 견딘다**. 실패 스텝은 **0콜로 기록**.

**셀 순서** = `(신규집합체 여부, 이미 열린 셀까지의 거리, 핀연소도 절벽, DB F_r_min, pair, feed)`.

f113 라벨 흡수 후 이웃 열의 비관 편향이 f105 **−0.0407**, f109 **−0.0516** 움직였고 그중
**82%/86%가 모델 기여**였다. f109의 하락폭은 라벨을 넣은 f113 열 자신(−0.0460)보다 컸다.

### 6.4 파생 규칙과 v1의 한계

셀마다 바뀌는 노브는 **10개뿐**(`CELL_OVERRIDE_KEYS`), 나머지는 부모 덱에서 그대로 승계
(테스트가 TOML 수준 전수 비교). 사람과 다른 곳 두 군데는 **둘 다 게이트하지 않는 노브**이고
규칙 쪽이 더 정직하다 — `cycle_tolerance_efpd` 30.0 → **45.0**(사람의 30은 617.5를 못 덮었다),
`near_miss_f_r` 1.65 → **1.66**. `random_seed`는 `2000 + hash(cell) % 800`(사용 시드 회피),
`cycle_target_efpd`는 DB 진실값 코어의 EFPD(**기록 전용**). 그리고 f113 보고서가 결함 #2로 기록한
불활성 `[constraints]` 블록을 **자동으로 뺀다** — **자동화가 사람의 실수를 복제하는 대신
사람의 교정을 승계하는 예.**

**v1이 할 수 없는 것(정직하게)**:
1. **원격 구간(ssh·scp·폴링)은 배선됐지만 한 번도 실행된 적이 없다**(`RecordingRunner`로만 검증).
   **첫 실전 실행은 반드시 사람이 지켜봐야 한다.**
2. **신규 집합체는 사전점검 후 정지** — DeCART2D 레그는 v1 범위 밖.
3. **OPEN 레시피는 한 셀의 증거이지 법칙이 아니다** — f113이 41/100을 낸 것은 교차-feed 엘리트
   부모가 26개 있던 셀이었기 때문. 부모가 얇은 셀에서 정체하면 **버그가 아니라 결과**이고,
   생성되는 모든 사전등록이 그 NULL 분기를 미리 적는다.
4. **핀연소도는 게이트되지 않는다** — 사전점검이 경고로 올리지만 **막지는 않는다**(프런티어
   라벨 자체는 모델에 유용하므로). 이 판단은 사람이 목표 목록을 만들 때 내려야 한다.
5. **메시는 챔피언이 바뀔 때마다 다시 돈다**(55셀 스윕 30–90분) — 연속 셀 개방 시 최대 비-MASTER 비용.
6. **동시 실행 보호가 없다** — 같은 `run_id`로 둘을 띄우면 원장이 뒤섞인다.
7. **"최적해"의 정의가 여전히 F_r 최소화다** — 사용자가 정의를 바꾸면(`user_criteria`) v1은
   따라가지 못한다. **v2 항목**(모드·드라이버는 이미 존재, 덱 승계 구조라 노브 교체만으로 가능).

**v2 항목**: 정책망 생성기 투입 / `user_criteria` 스위치 / 신규 집합체 완전 자동화 /
메시 증분화 / `(cyclen, F_r, 핀연소도)` 파레토 자동 삽입 / 드라이버 잠금 + 알림.

## 7. 그물망(mesh) 프로그램 — 설계공간 전체를 그린다

축은 **주기길이(EFPD) × 평균 방출연소도(GWd/tU)**, 격자는 **(노심평균 농축도 × 장전량)**.
방출연소도는 **모델 헤드가 아니라 평형 질량수지**로 낸다(Kropaczek 1993 원칙 — 평형에서
방출연소도는 종속량):

```
B_cycle = cyclen × P_th / M_HM / 1000        P_th = 3983 MW
B_d     = B_cycle × 241 / feed
```

`M_HM`은 스토어에서 실측 보정했다 — DeCART `MASS(g) TOTAL`이 단위길이·1/8 섹터당 값이라
환산계수를 38,854행에서 재봤더니 **3048.6 ± 1**(= 8섹터 × 381 cm = 3048과 0.02% 일치) →
`M_HM ≈ 101.7–102.2 tU`. 이 `B_d`는 MASTER 실측 `discharge_burnup` 38,220행을
**평균 −0.002%, sd 0.11%, 최대 0.57%**로 재현한다. (`coredeck.py`의 선언 상수 `hm_mtu = 104.8`은
실제보다 **2.7% 높다** — 여기서는 실측값을 쓴다.)

### 7.2 mesh v3 — 고농축 확장, 앵커, LRM 대조 (90셀)

### 7.3 다종(multitype) 그물망 — 3~5종 계단화

### 8.1 연료설계 축 (lat1600) — **Tier-0 판정 후 DeCART 지출 보류**

동기: LP 셔플로 F_r을 더 못 내리면 **집합체 자체를 평탄하게**(저 FF 격자) 설계한다.
체인 = **저 FF 격자 설계 → DeCART2D → TotalBatcher 라이브러리 재빌드 → 부트스트랩**.

**계획의 핵심 발견**: 24개 동결 `dec_FA` 템플릿이 **나쁜 Gd 레이아웃**을 갖고 있다 — 동일 노브
(u_high 5.00, gd_wt 6, n_gd 20)에서 템플릿 `2:2;5:2;6:4`는 **FF 1.1659**, ga80식 `1:1;4:1;6:4`는
**FF 1.1166** → **ΔFF 0.049 ⇒ ΔF_r 0.065**. **농축도 튜닝은 ~0.002, 레이아웃은 ~0.05 가치.**
그리고 **buildable-today 집합은 진다** — 4개 동결 레이아웃 위 984개 합법 설계 전수 채점에서
**정합 반응도의 모든 실현 설계가 대체 대상 ga80 타입보다 뾰족하다**(1.1658 vs E1의 1.146).
**템플릿 그대로의 DeCART 캠페인은 13분을 써서 F_r을 나쁘게 만든다** — 계획서의 가장 중요한
음성 결과. 레이아웃을 열면(89배치 × n_gd 12/16/20/24 = 5,874 설계) 뒤집힌다(1.1151 vs 1.146).
권고 지출은 4격자 = 1 DeCART 웨이브(~13분, `HOST_104` 전용) = `X1_X2`(E1_E2에 **150~290 pcm
반응도 정합** — FF만 분리) + `X3_X4`(평탄 극단). `ncomp 38 → 42`(TotalBatcher 실증 천장은
40 fuel COMP → **MASTER 미실증 리스크**).

**TIER 0 판정(2026-08-09)** — 사전등록 반증조건 채점:

| 조건 | 기준 | 측정 | 판정 |
|---|---|---|---|
| **F1** 전이 없음 | FF_hot 기울기 < 0.66 | 3점 0.912 → **7점 0.508** | **발화** |
| F2 부호 오류 | A1 ≥ A0 또는 A2 ≤ A0 | 1.5137 < 1.5207 < 1.5483 | 미발화 |
| F3 분해능 부족 | A0 복제 스프레드 > 0.005 | **0.0000** | 미발화 |
| F4 거래가 이득을 삼킴 | CBC>1550 또는 F_q>2.41 | A1 통과 / **C5 CBC 1669.7 위반** | 부분 발화 |

3점만 보면 확증에 가까웠으나(기울기 0.912, R² 0.980) **dose point를 7점으로 늘리자 F1이 발화**했다.
**C6 널테스트가 순진한 분해식도 반증했다** — 축약식 `F_r = A·p_boc·FF_hot`은 "hot 슬롯만 중요"를
함의하므로 C6(A2 전량)과 A2(A8_A2)의 F_r이 같아야 하는데(둘 다 FF_hot 1.178) 실측은
**1.8175 vs 1.5483, 0.269 차이**다. **`p_boc`는 상수가 아니다.**
고정 p_boc 적합 R² **0.142** vs 측정 node_peak 적합 `F_r = 0.7255·(node_peak × FF_hot) + 0.466`
R² **0.901**.

**결론**: FF 레버는 실재하나 **2차항**이다. 단일 패턴 치환은 도박(9쌍 중 F_r 하락 1건, 최대 +0.297).
**엘리트 24패턴에 평탄연료(E3_E4)를 일괄 적용**하면 F_r **15/24 개선**(중앙값 −0.0069),
**map_cov 24/24 개선**(평균 −0.0255), **cyclen 24/24 개선**(+0.47 EFPD), **24/24 feasible 유지**,
대가 CBC +42.9 ppm. 그러나 같은 기간 **장전모형 탐색만의 F_r 이득은 −0.057**로 연료 레버 중앙값의
**8배**다. **연료는 실재하지만 2차 레버.**
**판정: 템플릿 그대로의 DeCART 지출 보류.** 단 반응도 정합쌍 X1_X2는 오늘 측정이 오히려 정당화를
강화했다(실패 원인이 정확히 반응도 불일치로 특정됐으므로).

**lat1600 후속 재심사**(`opmodel/OPSCREEN.md`, 2026-08-11): 보정 운전점 모델로 다시 스크린하니
**T5_T6에는 운전점이 없다** — f121에서 **1600 게이트를 125–137 ppm 초과**(실측 1725/1737),
f117에서 102 ppm 초과. 그리고 **고정 패턴에서 가장 평탄한 연료가 가장 나쁜 F_r을 냈다**
(T5_T6 1.5795 vs E1_E2 1.5207) — T5/T6이 200 pcm 미만 차이라 패턴의 E1/E2 존잉이 단일 타입 장전으로
붕괴했기 때문. **FF가 아니라 두 fresh 역할 간 반응도 대비(contrast)가 node_peak을 잡는다.**
산출물: `fr_arms.py`(13 arm, `--reference flat|minfr`), `fr_arms_pattern.txt`(618자 포터블 패턴),
`fr_transfer.py`(다패턴 전이 스윕, 재개 가능), `realize_lat1600` / `templates_lat1600` 체인.

**핀 피치/반경 축**(`pitch_radius_readiness.md`, **계획만**): 집합체 봉투(assembly pitch
20.7772 cm = MASTER `%GEN_GEO wide`)를 동결하면 **MASTER 노심모델·메시·재시작이 전부 유효**하고
하드 블로커가 없다. 단 **핀 피치는 비대칭**(상한 +1.06% — 16×1.285 = 20.560 cm에 물 간극 0.2172 cm뿐,
하한은 넓다), **반경은 본질적으로 시끄럽다**(`u_mass` 스케일이 138.8의 0.5%라 +0.5%에서 z ≈ 2),
**피치 ≲2%가 조용하지만 틀린 위험구간**이며 **앙상블 분산은 이것을 절대 못 잡는다**
(전 멤버가 같은 매니폴드에서 학습돼 **함께** 틀린다) → 채널별 z-가드 + DeCART 블라인드 프로브 필수.

### 9.3 알려진 결함과 함정 (재발 방지)

1. **`lpopt report`의 "Best verified loading patterns"는 목적과 무관하게 `cycle_target_efpd`
   거리로 랭킹**한다 → F_r 목적 캠페인에서 진짜 우승자가 표에 없다. 권위 있는 값은 `state.json → best`.
2. **`state.json → best_overall`은 CBC를 보지 않는다** — CBC 위반 raw 코어를 올린다.
   **우승자를 인용하기 전에 CBC 필터를 걸 것.**
3. **`min_fr_max_cycle`의 핀 게이트는 예측만 본다** — MASTER가 핀연소도를 측정하지 않고
   `is_feasible()`이 결측 `max_pin_burnup`을 **PASS로 처리**하므로(엘리트/best-tracking 기아 방지)
   "feasible"이라 보고된 코어가 납품 불가일 수 있다. `optimize` 검증 경로는 핀연소도를
   **수확조차 하지 않는다**(플래그가 `[design]`에만 있어 optimize 덱에서 도달 불가).
4. **`CaseAssetResolver.promote()`는 오랫동안 호출자가 없었다**(레벨-1 캐시 미충전). 측정 비용:
   f129 A/B에서 같은 4라벨에 **7체인 → 4체인**, 발산했던 2패턴 **구제**. 2026-08-16 배선 수정.
   **호출은 반드시 `_maybe_purge()` 이전.**
5. **`ablation_wave._done()`이 하네스 실패를 "완료"로 취급**해 재개 시 조용히 건너뛰었다 →
   `verify.PHYSICS_KILL_FAILURES` 기반 분류로 수정(`tests/test_ablation_resume.py` 10케이스,
   실제 사고 파일 리플레이 포함).
6. **웨이브 계획이 부모 내부에서만 중복 제거**해 7체인(3.2% 예산) 낭비 → **전역 `record_id` 중복 제거.**
7. **덱을 저장소 루트가 아닌 곳에 두면 자산 해석이 전부 `unresolved`**(리졸버가 상대경로를 덱
   디렉터리 기준으로 푼다).
8. **한 실행에 리졸버는 하나뿐** — ga80과 paramA를 한 덱에 담으면 paramA 체인이 전부 죽는다. **분리 덱 필수.**
9. **디스크가 실질 제약** — `HOST_199`에서 `runs/`가 144 GB까지 자라 웨이브 중 0바이트가 됐고,

  DB 실측으로 반증된 전례가 있다.
