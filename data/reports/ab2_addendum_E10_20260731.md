## 1. Why this arm exists, and why it is allowed

Round 1's verdict (`data/reports/ab2_verdict_20260731.md`) met the
falsification condition registered in the pre-registration §1: zero of five
arm×target-axis comparisons established a gain, so **loss/label engineering is
not the lever for this residual**. §1 named the permitted successors verbatim:

> the next round must move to a different mechanism (more labels in the
> deficient cells, verify-many-then-select, or **an ensemble/variance reduction
> change**) — **not** to a bigger version of the same knob.

E10 is the third of those three. `--ensemble 10` is not a bigger version of a
round-1 knob — A1/A2/A3 were all loss-term changes and all three are dead. It is
a different mechanism entirely: the residual under attack is **variance** (§1 of
the pre-registration: "Systematic bias on all of these is already removed …
What is left is VARIANCE"), and averaging more independently-seeded members is
the textbook variance reduction that does not touch the loss, the labels, the
normalisation or the serve contract. **E10 is admissible under the round-1
consequence.** No re-litigation of round 1 is implied or permitted by it.

### 1.1 The single change

E10 = the A0 control recipe of pre-registration §3.1, with `--ensemble 5`
replaced by `--ensemble 10`. Same store snapshot, same `data/splits/S1.json`,
same `cond_schema=v6`, same width/blocks/head, same epochs, same every other
flag. The control is **A0**, exactly as in round 1 — never the champion
`20260729_054749`, because `arm − champion` confounds the model change with the
store change (pre-registration §3, §5.1).

### 1.2 Provenance premises I cannot verify locally, recorded as premises

The coordinator states E10 was trained from the identical pinned snapshot with
five additional seeds (`20260721..20260725`) beyond A0's `20260716..20260720`.
**No E10 run metadata, `meta.json`, `train.log` or model directory exists in
this repo or the scratchpad** — the only local artifact is `rows_ab2E10.csv`.
So the following are **assumed, not verified**, and are recorded here so the
verdict cannot later be read as having confirmed them:

| premise | status |
|---|---|
| E10 trained on the same `records.parquet` snapshot (sha `f01526cc…`) | **assumed** |
| E10 trained on the same `S1.json` (sha `02d095d8…`, verified for the split file itself) | **assumed** for E10's use of it |
| E10 members 1–5 are seeds `20260716..20260720` (i.e. A0's members) and 6–10 are new | **assumed** |
| E10 differs from A0 in `--ensemble` and nothing else | **assumed** |
| all six per-cell calibrations fitted in one pass (pre-registration §7) | **assumed** |

Two of these matter for interpretation and are flagged now, before any number
exists:

* **If E10's first five members ARE A0's members**, then E10 ⊃ A0 and the
  comparison is a *nested* one: E10 cannot differ from A0 by chance in the way
  two independently-seeded arms can, and any measured difference is attributable
  to the five added members alone. This is the *favourable* reading and it makes
  the paired comparison unusually clean.
* **If E10 was retrained from scratch with ten fresh seeds**, then E10 − A0
  confounds "more members" with "different members", and a gain cannot be
  attributed to ensemble size alone. The verdict will state which reading it is
  relying on and will not claim the stronger one without evidence.

Nothing in the decision rule below depends on resolving this; it changes what a
PROMOTE-candidate would *mean*, not whether one is declared.

## 2. The decision rule — fixed before any E10 result exists

### 2.1 Surface, estimator, control: inherited unchanged

Identical to pre-registration §5.1 and to round 1's execution:

* **Unit:** the design cell. **Rows:** the S1 holdout restricted to the frozen
  36-cell list (`groups.curriculum_val_by_cell`), 3,207 rows. Scored on the same
  rows in the same order as A0 — that alignment is the pairing.
* **Estimator:** `lpopt/model/ab_paired.py` `paired_cell_bootstrap`,
  `method="bca"`, `aggregate="median"`, `reps=2000`, `alpha=0.05`, `seed=0`,
  sign-flipped so `theta > 0` always means "E10 beats A0".
* **Metric primitive:** `flat_metrics.cell_mae`, `min_rows = MIN_CELL_ROWS = 8`
  (registered default), restricted to the frozen cell list by
  `flat_ab._restrict`.
* **Control:** A0. **Never** the champion.
* `n_cells < 6` → percentile fallback, announced; `n_cells < 3` →
  `insufficient`; a point-mass resample → `degenerate`. Both no-evidence methods
  fail every gain AND every harm test. 36 cells clears both floors.

### 2.2 Target axes — all five variance axes

Ensemble averaging is **axis-agnostic**: it reduces the variance component of
every head's prediction at once, and there is no mechanism by which it would
help `cbc_max` and not `node_peak`. Round 1's arms each named one or two axes
because each was a targeted loss term with a specific causal story; E10 has no
such story to tell, so restricting it to a favoured axis would be unregistered
cherry-picking. The registered axis set is therefore all five variance axes:

| axis | metric key | units |
|---|---|---|
| `node_peak` | `T_cell_mae_node_peak` ≡ `M7_cell_mae_node_peak` | — |
| `map_cov` | `M7_cell_mae_map_cov` | — |
| `f_q` | `T_cell_mae_f_q` | — |
| `cbc_max` | `T_cell_mae_cbc_max` | ppm |
| `cyclen` | `T_cell_mae_cyclen` | EFPD |

All five are `flat_metrics.cell_mae` with `higher_is_better=False`. Four come
from the frozen `AB2_TARGET_METRICS` tuple; `map_cov` cell-MAE has no `T_`
key, so `M7_cell_mae_map_cov` is used — the *same function with the same
kwargs*, so this is a naming detail, not a new metric.

**Registered now to prevent a double-counting complaint later:** `node_peak` and
`map_cov` cell-MAE appear in BOTH the gain set (§2.3) and the non-regression
rails (§2.4). This is deliberate and is how `ab_paired` is designed to be read —
"the harm's upper bound is the negated lower bound of the gain, so one interval
answers both questions and they can never disagree" (module docstring). One
bootstrap is computed per axis and consulted twice. It is not two tests.

### 2.3 Condition 1 — the promotion bar, and why it is stricter than round 1's

**E10 PROMOTES only if BOTH hold across the five axes of §2.2:**

1. **at least TWO axes have `ci_lo > 0`** (`PairedDiff.establishes_gain`), and
2. **ZERO axes are established worse** (no axis may have `ci_hi < 0`).

Round 1 required each arm to establish a gain on *its own* one or two named
axes. E10's bar is deliberately different in shape and strictly harder to clear
by luck, for three reasons, all registered before the result:

* **Multiplicity.** Testing five axes at α = 0.05 each gives roughly a 1 − 0.95⁵
  ≈ 23% chance that at least one axis clears by chance under a true null. A
  one-axis-of-five rule would be a near-coin-flip dressed as an interval.
  Requiring two independent axes to clear collapses that to ≈ 2%, without
  needing an unregistered multiplicity correction whose form I would be choosing
  after seeing the spread.
* **The mechanism's own prediction.** If ensemble averaging works, it works
  everywhere. A single isolated axis clearing while the other four sit flat is
  *evidence against* the mechanism, not for it — it looks like noise, not like
  variance reduction. Requiring two makes the rule test what E10 actually
  claims.
* **Cost.** This is the load-bearing one. **E10 doubles serve cost: 10 forward
  passes per candidate instead of 5, which takes a campaign inference wave from
  ~20 min to ~40 min.** Every future campaign wave, every acquisition scoring
  pass, every boundary probe pays that, permanently, for as long as E10 is
  champion. A one-axis marginal gain does not buy back a 2× standing tax on the
  search loop. Two axes is the point at which the win is broad enough to be
  worth doubling the cost of every downstream thing. **A cheaper arm would have
  been allowed a cheaper bar; E10 is not, and that asymmetry is registered here
  rather than argued after the fact.**

The "zero established-worse" clause exists because a variance reduction that
*degrades* an axis is not a variance reduction — it is a different model. Round
1 showed all three arms established worse on `cyclen`; if E10 does the same on
anything, the ensemble story is false regardless of what else improves.

### 2.4 Condition 2 — non-regression rails, inherited verbatim

Every metric in `flat_ab.HARM_MARGINS` must satisfy `bounds_harm(margin)`,
i.e. `harm_upper = −ci_lo < ε`, at the round-1 epsilons, unchanged:

| axis | ε |
|---|---:|
| `M2_flat_tercile_rho_{node_peak,map_cov}` | 0.01 |
| `M3_norm_p_at_8_{node_peak,map_cov}` | 0.01 |
| `M5_cell_rho_{f_q,cyclen}` | 0.02 |
| `M7_cell_mae_{node_peak,map_cov}` | 0.005 |
| `M7_abs_bias_node_peak` | 0.005 |

`M5_cell_rho_f_r` remains scored, reported, and **excluded from the verdict**
under the F_r deferral (`flat_ab.FR_HARM_METRIC`, user decision 2026-07-26).
A straddling interval is **not** evidence of equivalence (pre-registration
§5.3) and routes to HOLD, never to PROMOTE.

### 2.5 Condition 3 — not applicable

Pre-registration §5.4's coverage check is specific to A1's trajectory labels.
E10 has no label-coverage dependency. **Not applied.** (Round 1 also recorded
that the frozen holdout is 100% Dataset P, which makes any P-restriction an
identity on this surface in any case.)

### 2.6 Verdicts

* **PROMOTE-candidate** — conditions 1 and 2 both hold. Earns a gate attempt
  against the champion per pre-registration §5.7; does not promote by itself.
* **HOLD** — condition 1's intervals straddle without any axis established
  worse, and condition 2 does not fail.
* **REJECT** — condition 2 fails (an enforced harm bound exceeded), **or** any
  of the five target axes is established worse (§2.3 clause 2).
* **ESCALATE** — a target axis returns `insufficient` or `degenerate`.

### 2.7 Power, reproducibility, and reporting

* **MDE₈₀** is computed per axis from the same bootstrap that produces the
  interval (`PairedDiff.mde`, `MDE_POWER = 0.80`), and an axis whose observed
  effect falls below its own MDE₈₀ is reported as **underpowered**, never as
  null (pre-registration §5.8).
* **Any harm violation or any established-worse axis is re-run at bootstrap
  seeds 0–4** and the verdict states whether it reproduces at every seed. A
  violation that does not reproduce is reported as seed-sensitive and escalated
  rather than acted on.
* The **cost line** (§2.3) is carried in the verdict table itself, so the
  cost-benefit trade is visible at the point of decision rather than in a
  footnote.
* Every interval, note, level, method and MDE is written to
  `data/reports/ab2_verdict_E10_20260731.json`.

### 2.8 Falsification for this addendum

Registered now: **if E10 fails to clear the two-axis bar, the conclusion is that
ensemble/variance reduction at this scale is not the lever either**, and the
remaining round-1 §1 successors — more labels in the deficient cells, and
verify-many-then-select — become the only admissible mechanisms. In that case
the specific thing that is falsified is "the residual is member-to-member
variance that averaging can cancel"; the live alternative becomes "the residual
is label noise or missing coverage, which no amount of averaging touches",
pointing at the `flatness_noise_measured_20260726` noise-floor work rather than
at a bigger ensemble. **Escalating to `--ensemble 20` is explicitly forbidden by
this addendum** — that would be a bigger version of the same knob, which is the
exact move round 1's §1 consequence prohibits.
