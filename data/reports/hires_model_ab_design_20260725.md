**목적**: 사용자 지시 "학습용 GPU는 VRAM 96GB로 충분하니 **파라미터 수와 분해능을 충분히 늘려** 최적 결과를 내는 AI 모델로 개선해"를 물리적으로 옳게 해석하여 A/B arm 세트를 사전등록한다.

**베이스라인**: 현 챔피언 `data/models/20260724_213535` (재학습 #7).
**선행 근거**: `data/reports/cyclen_nodepeak_resolution_20260725.md`(분해능 실증), `data/reports/model_accuracy_20260725.md`(fold 정의·프로토콜).
**본 문서의 신규 계산 3건** (§1, §2, §3): ① 맵 라벨 해상도 실측, ② 챔피언 학습 파라미터 실측, ③ **확산 출력맵 물리프라이어 실증**(신규, 설계를 좌우함).

## 핵심 요약 (한 눈에)

1. **맵 라벨 해상도 상한을 실측했다: 집합체(assembly) 단위 radial 69슬롯 × 4채널 = 레코드당 276 float.** 축방향 0, 핀 0. `maps.npz`는 `(4, 9, 9) float16`이고 69개만 유한, 나머지 12은 NaN 패딩이다. **따라서 "맵 헤드 출력 해상도를 서브셀로 올린다"는 축은 오늘 라벨로는 원리적으로 불가능**하다 — 상한이 곧 현재값이다. 다만 MASTER 원본에는 **축방향 25평면(EDIT 6, 이미 파싱되는 `MAS_SUM` 안)** 과 **핀 3-D 16×16×25 × 69집합체(`MAS_PPI`)** 가 존재하며 전량 폐기되고 있다(§1). 해상도 확대의 진짜 경로는 모델이 아니라 **프로듀서 측 harvest**다.

2. **챔피언 #7이 실제로 학습한 파라미터는 6,298개다** (전체 3,159,291개 중 0.2%). `--freeze-trunk-cyclen`이 stem/blocks/films/head_trunk/conv_head를 전부 동결했고, 학습된 것은 `map_head`(644) + `mu_head`(2,056) + `log_sigma_head`(2,056) + `quantile_head`(1,542)뿐이다. **즉 서빙 챔피언의 공간 표현 전체는 2026-07-21 이후 동결된 트렁크 위에 얹힌 644-파라미터 1×1 선형 판독기다**(§2). 선행 보고서 §2.7의 "`map_peak_weight`는 캘리브레이션만 고쳤고 표현은 바꾸지 못했다"가 여기서 기계적으로 설명된다 — **표현은 바뀔 수 없는 상태였다.** 이 사실은 A/B 설계의 대조군 정의를 바꾼다(§4의 B1).

3. **신규 실증 — 확산 출력맵 물리프라이어는 학습 파라미터 0개로 셀내 순위의 대부분을 이미 갖고 있다.** 이미 harvest된 집합체별 k-inf 곡선만으로 1군 조격자 확산 고유치를 풀어 만든 출력맵 프라이어(자유 파라미터 2개: M², 외삽거리)의 성능은 **셀내 ρ: node_peak 0.436 / map_CoV 0.592 / F_r 0.422**다(§3). 비교 기준이 결정적이다 — **cyclen 물리프라이어의 셀내 ρ는 0.064(CI가 0 포함)였는데도 잔차 학습이 0.726을 만들어냈다.** 즉 이번 프라이어는 성공한 선례보다 **7~9배 강한 출발점**이다.

4. **그리고 이 프라이어는 CNN과 스펙트럼이 정확히 상보적이다.** 파수 증가에 따른 모드별 진폭 상관이 CNN은 **0.897 → 0.593으로 단조 하락**하는 반면, 프라이어는 **0.545 → 0.861로 단조 상승**한다. 나이퀴스트 대역 파워비도 CNN 0.71(인분포)·0.41~0.57(외삽) 대 프라이어 **0.862**다(§3.3). 물리적으로 당연하다 — 프라이어의 고주파 성분은 셔플 패턴이 만드는 **국소 k-inf 체커보드에서 직접 온다**. **이것이 "왜 단순 폭 확대보다 나은가"의 핵심 근거다**(§8).

5. **학습 비용은 병목이 아니다.** 전량 학습(width 160/6블록, 5멤버 **병렬**)이 **2,263초 = 38분**이었다(`20260721_105824/train.log`). 96GB VRAM에서 파라미터를 4배로 키워도 arm당 2~3시간이며, 7개 런 전체가 **약 8 GPU-시간**이다. 따라서 arm 수를 아끼기보다 **단일인자 분리에 투자하는 것이 옳다**.

## 1. 맵 라벨 해상도 실측 — 해상도 상한 확인

사용자 요구사항 "EDIT5 라벨이 실제 어떤 해상도를 갖는지 먼저 확인하라 — 라벨 해상도가 상한이다"에 대한 실측 답변이다.

### 1.1 저장된 라벨

`data/store/maps.npz` 직접 검사 (28,130키):

| 항목 | 실측값 |
|---|---|
| 배열 shape | **`(4, 9, 9)`** |
| dtype | **`float16`** |
| 유한값 개수 | **69** (나머지 12은 `NaN` 패딩 — 쿼터 삼각형 밖) |
| 채널 순서 | `("boc_power", "eoc_power", "eoc_burnup", "eoc_kinf")` (`lpopt/data/edit5.py:41` `MAP_KEYS`) |
| 키 | `maps_key == record_id` (64-hex SHA) |
| **레코드당 라벨 총량** | **276 float** |

### 1.2 MASTER 원본에서의 네이티브 해상도

`lpopt/data/edit5.py`가 유일한 생산자다. EDIT5 원문은

```
   SUMMARY EDIT 5 : ASSEMBLY INFORMATION
          FIRST  LINE: ASSEMBLY BATCH ID
          SECOND LINE: ASSEMBLY POWER
```

로 **집합체당 1개 float**이다. 서브집합체 radial 메시도, 축방향 인덱스도 EDIT5에는 없다.

**9×9 쿼터 접기는 손실이 아니다.** MASTER 덱 자체가 쿼터코어 모델(`MAS_PPI` 헤더 `NX NY NZ : 10 10 27`, `NSYM : 1`; `lpopt/design/coredeck.py:138`)이라 EDIT5가 **애초에 SE 쿼터만 출력**한다. 장전 패턴도 쿼터 대칭으로 구성된다(`lpopt/vendor/masterrl/domain.py:62-63`: 69슬롯 × 다중도(1/2/4) = 241집합체). `edit5._quadrant`는 평균이 아니라 무손실 재라벨이며, `net.py:204-209`의 map_head gather가 **동일한 인덱스 집합**을 쓴다.

### 1.3 폐기되는 해상도 — 진짜 지렛대는 여기 있다

| 차원 | MASTER 출력에 존재 | maps.npz 저장 | 손실 |
|---|---|---|---|
| Radial (집합체) | 69 쿼터 슬롯 | 69 | 없음 |
| **Radial (핀)** | **16×16 × 69집합체** (`MAS_PPI` `PIN 3-D POWER/BURNUP`) | 0 | **100%** |
| **축방향** | **25평면** — 코어평균(`SUMMARY EDIT 6`, **이미 파싱 중인 `MAS_SUM` 안**) + 집합체별(`MAS_PPI`) + 핀별 3-D | 0 | **100%** |
| 연소 스텝 | EDIT5에 30스텝 | 2 (BOC/EOC) | ~93% |

`lpopt/vendor/masterrl/burnup.py:139-219`는 핀 연소도 25×16×16=6,400값을 읽어 **스칼라 1개**(`max_pin_burnup`)로 축약하고, `master.py:818-850`은 **69집합체 중 1개만** 파싱한다. 핀 출력(power)은 **한 번도 읽히지 않는다**. 그리고 `lpopt/search/verify.py:216,334`에 따라 `MAS_PPI`/`MAS_SUM`은 `harvest_maps=True`가 아니면 런 종료 시 **삭제**된다.

### 1.4 설계에 미치는 결론 (중요)

- **"각 집합체를 2×2/3×3 서브셀로 전개" 또는 "업샘플 디코더로 맵 헤드 출력 해상도 상향"은 오늘 라벨로는 지도학습이 불가능하다.** 감독 신호가 69슬롯에서 끝나므로, 서브셀 출력은 어떤 손실로도 학습되지 않는다(정규화 항으로만 존재하게 되어 순수한 파라미터 낭비 + 과적합 위험).
- 따라서 본 설계는 **출력 해상도가 아니라 "실효 분해능(effective resolution)"** 을 늘리는 데 96GB를 쓴다. 실효 분해능 = 69슬롯이라는 고정 격자 위에서 **모델이 실제로 구별해낼 수 있는 최소 차이**(Δ₇₅/셀내SD)이며, 선행 보고서가 정량화한 병목이 정확히 이것이다.
- **동시에 즉시 착수해야 할 별도 처방(모델 밖)**: `SUMMARY EDIT 6`의 축방향 25평면은 **이미 파싱되는 `MAS_SUM` 파일 안에 있고 `edit5._split_sections`가 이미 섹션 6을 딕셔너리에 담고 있다**(`parse_mas_sum`이 읽지 않을 뿐). 즉 **새 MASTER 실행 없이 파서 몇 줄로 축방향 라벨을 켤 수 있다**(단, 기존 28,100건 맵에는 소급 적용 불가 — 신규 생산분부터). 축방향은 `ao_abs`(현재 "측정 불가" 판정)와 축방향 출력 평탄화를 여는 유일한 경로다. **본 A/B 범위 밖이나, 우선순위 최상위의 후속 작업으로 기록한다.**

## 2. 챔피언이 실제로 학습한 파라미터 — 대조군 정의를 바꾸는 사실

`data/models/20260724_213535/member_20260716/meta.json`의 `n_params` 필드는 **6,298**이다. 이 필드는 `train.py:1447` `count_parameters(m.model)`이고, `count_parameters`는 `requires_grad=True`만 센다(`net.py:235-237`).

체크포인트 `model.pt`를 직접 세면 **총 3,159,291개**다. 차이의 원인은 `--freeze-trunk-cyclen`이다 — `_apply_freeze_trunk_cyclen`(`train.py:894-925`)이 `stem` / `blocks` / `films` / `head_trunk` / `conv_head`를 전부 `requires_grad=False`로 만든다. 남는 학습 대상은:

| 모듈 | 파라미터 |
|---|---:|
| `map_head` (1×1 Conv2d, W=160 → 4) | **644** |
| `mu_head` (Linear 256→8) | 2,056 |
| `log_sigma_head` (Linear 256→8) | 2,056 |
| `quantile_head` (Linear 256→6) | 1,542 |
| **합계** | **6,298** ✓ |

트렁크의 출처는 `--init-from data/models/20260721_105824`이며, 그 런이 마지막 전량 학습(width 160, 6블록, cond v5, best_epoch 69, 3,159,291개 전량 학습)이다.

**세 가지 귀결**:

1. **선행 보고서의 "6.3만 파라미터"는 이 필드를 오독한 것**이고, 실제 규모는 3.16M/멤버 · 앙상블 15.8M이다. "6.3만 파라미터·4.3만 행 규모에서 ViT는 부적합"이라는 §3.8 R8의 판정 근거 수치는 정정이 필요하다(결론 자체는 데이터량 논거로 여전히 유효).
2. **맵 헤드는 644개 파라미터의 선형 판독기다.** 6개 잔차블록(3×3 conv 12회)을 통과해 이미 평활화된 최종 특징에서 1×1 conv 하나로 69슬롯을 읽는다. **고주파 성분을 복원할 경로가 구조적으로 존재하지 않는다.**
3. **`map_peak_weight` A/B(§2.7)는 동결 트렁크 위에서 수행됐다.** "손실 가중은 표현을 바꾸지 못한다"는 결론은 그 실험 설계에서는 **필연**이었다 — 표현이 동결돼 있었으므로. 이 결론을 "손실 설계 일반"으로 확장 적용해서는 안 된다. **따라서 모든 구조 arm의 대조군은 트렁크가 학습되는 런이어야 한다(§4 B1).**

## 3. 신규 실증 — 확산 출력맵 물리프라이어 (설계의 중심축)

선행 보고서 §3.8 R1의 처방("node_peak은 집합체 kinf 기반 근사 출력지도 또는 2군 확산 저차해")을 **실제로 구현해 채점했다.** 이것이 본 설계에서 R1을 1순위로 올리는 근거다.

### 3.1 프라이어의 정의

기존 `lpopt/model/physics_prior.py`의 `assembly_rho(vec, burnup)`를 슬롯별로 그대로 재사용한다(cyclen 프라이어가 이미 쓰는 함수, 즉 **새 물리 가정이 없다**):

1. 각 69슬롯 `j`에 대해 셔플 체인을 fresh origin까지 추적(`FeatureEncoder._trace_chain`) → harvest된 k-inf(BU) 곡선을 얻는다.
2. 사전(a-priori) 연소도 `b_j = (age_j−1)·NOMINAL + NOMINAL/2`에서 `rho_j = assembly_rho(vec_j, b_j)` → `kinf_j = 1/(1 − rho_j/10⁵)`.
3. 쿼터를 17×17 전노심으로 미러 전개(241 노드).
4. **1군 조격자 확산 고유치 문제**를 푼다: `A φ = (1/k)·(h²/M²)·kinf·φ`, 여기서 `A`는 5점 라플라시안 + `h²/M²` + 경계항(연료 밖 이웃은 외삽거리 `ex`의 알베도), `h = 20.78 cm`(APR1400 피치).
5. 출력 `P_j ∝ kinf_j · φ_j`, 전노심 평균 1로 정규화 → 쿼터 69슬롯으로 되읽는다.

**자유 파라미터는 (M², ex) 단 2개**이며, cyclen 프라이어의 (alpha, beta)와 동일하게 **셀별이 아닌 전역 상수**다. 따라서 셀 라벨 정보가 새어 들어갈 수 없고, 셀내 지표는 정직하다.

### 3.3 결정적 근거 — 스펙트럼 상보성

선행 보고서 §3.6과 **동일한 프로토콜**(69슬롯만 남기고 슬롯 평균 제거, 동일 창 공유, 2-D FFT, 반경 파수 대역)로 프라이어를 채점했다(732행):

| 파수대 | 모드수 | 실측 파워 비중 | **프라이어** 파워비 | **프라이어** 모드 ρ | 참고: **CNN** 파워비 (fold B) | 참고: **CNN** 모드 ρ (fold C) |
|---|---:|---:|---:|---:|---:|---:|
| k 0.00–0.13 | 4 | 28.5% | 1.483 | 0.545 | 1.001 | 0.897 |
| k 0.13–0.25 | 16 | 45.7% | 0.944 | 0.721 | 0.812 | 0.877 |
| k 0.25–0.36 | 16 | 11.1% | 0.981 | 0.712 | 0.785 | 0.785 |
| k 0.36–0.47 | 20 | 8.4% | 1.075 | 0.773 | 0.761 | 0.717 |
| **k 0.47–0.72 (나이퀴스트)** | 24 | 6.3% | **0.862** | **0.861** | **0.713** | **0.593** |

**두 모델의 스펙트럼 오차 구조가 정확히 반대다.**

- CNN: 모드 상관이 파수 증가에 따라 **단조 하락**(0.897 → 0.593). 고주파를 못 본다.
- 프라이어: 모드 상관이 파수 증가에 따라 **단조 상승**(0.545 → 0.861). **저주파를 못 본다**(최저주파 파워비 1.483 = 반경 기울기를 48% 과대).

물리적으로 자명하다. 프라이어의 고주파 성분은 **셔플 패턴이 만드는 국소 k-inf 대비에서 직접** 나오므로 정확하고, 저주파 성분은 조격자 1군 확산의 조잡한 누설·경계 처리와 연소 피드백 재분포 누락 때문에 부정확하다. CNN은 그 반대다 — 저주파는 학습으로 잘 맞히고(파워 비중 74%가 여기 있으니 손실이 여기에 지배된다) 고주파는 conv 캐스케이드가 평활화한다.

**⇒ `예측 = 프라이어 + CNN 잔차` 분해는 각 구성요소를 그것이 잘하는 대역에 배치한다.** 이것은 파라미터를 더 주는 것이 아니라 **파라미터가 무엇을 표현하도록 요구받는가를 바꾸는 것**이다.

### 3.4 정직한 반증 — 프라이어 단독으로는 붕괴 구간을 못 고친다

가장 중요한 구간(선행 보고서 §2.5 "이미 평탄한 후보군")에서 프라이어 **단독** 성능:

| 층 (실측 CoV 3분위) | n | 프라이어 CoV 쌍 부호적중 | 프라이어 peak 쌍 부호적중 | 참고: 챔피언 CoV 쌍적중 (fold C) |
|---|---:|---:|---:|---:|
| 전체 | 732 | 0.718 (15,307쌍) | 0.633 | 0.802 |
| **이미 평탄(하위 1/3)** | 244 | **0.570** (1,584쌍) | **0.484** | **0.692** |
| 중간 | 244 | 0.621 | 0.538 | 0.683 |
| 첨예(상위 1/3) | 244 | 0.667 | 0.636 | 0.757 |

**프라이어 단독은 붕괴 구간에서 챔피언보다 나쁘다**(0.570 vs 0.692). 따라서 "프라이어를 넣으면 §2.5 붕괴가 해결된다"는 **주장할 수 없다**. 주장할 수 있는 것은 정확히 이것뿐이다:

> 프라이어는 (ⅰ) 학습 파라미터 0으로 셀내 순위의 60~74%를 이미 제공하고, (ⅱ) CNN이 감쇠시키는 고주파 대역에서 모드 상관 0.861을 갖고, (ⅲ) 동적범위 압축이 없다(SD비 1.10 vs CNN 0.573). 잔차 학습은 CNN의 용량을 (ⅰ)의 몫에서 해방시켜 고주파 잔차에 집중시킨다.

(ⅰ)의 구조적 선례가 cyclen이다: 프라이어 단독 셀내 ρ 0.064 → 잔차 추가 0.726. **이번 프라이어의 출발점은 그때보다 7~9배 높다.**

### 3.5 프로브의 한계 (사전 고지)

1. 표본 732행은 fold C 정의가 아니라 **전 코퍼스 층화 표본**이다. post-selection(모델 제안 후보) 오염이 제거되지 않았다. 판정 단계에서는 fold C 무오염 슬라이스로 다시 잰다.
2. (M², ex)를 전체 표본에서 그리드 탐색했으므로 **약한 낙관 편향**이 있다. 실제 아티팩트는 train 스플릿에서만 적합한다.
3. 1군·조격자·균일 D/Σa·사전 연소도 가정은 모두 leading-order다. 이는 결함이 아니라 설계 의도다(잔차가 나머지를 배운다).
4. 축방향 무시. 프라이어는 radial 전용이므로 축방향 효과는 잔차로 흡수된다.

### 4.2 arm별 교락(confounding) 관리

- A1은 파라미터를 +1.15M 늘린다 → **A5가 그 4배 용량을 순수하게 대조**하므로, A1이 이기고 A5가 지면 "구조지 용량이 아니다"가 확정된다. 이것이 A5를 **귀무가설 arm으로 반드시 돌려야 하는 이유**다.
- A2는 파라미터를 사실상 늘리지 않는다(+6천) → **용량과 완전히 분리된다.** A2가 이기면 그것은 100% 표현/분해 구조의 효과다.
- A3은 파라미터를 전혀 늘리지 않는다.
- A4는 입력 채널만 늘린다(+2채널 → stem에서 +2,880).

## 7. 사전등록 결정 규칙

**승격 조건** (아래를 모두 만족해야 챔피언 후보):

1. **P1**에서 node_peak 또는 map_CoV의 Δ₇₅/SD가 B1 대비 **≥ 0.15 개선**되고, 다른 3타깃에서 0.05 이상 악화 없음.
2. **T1** 정직 게이트 통과 (무회귀).
3. **S1**에서 cyclen·F_r 셀내 ρ가 B0(현 챔피언) 대비 하락하지 않음 (짝지은 부트스트랩 CI 하한 ≥ −0.02).

**기각 조건**:

- A5(순수 용량)가 1차 지표에서 +0.02를 넘지 못하면 **"단순 폭 확대 무효" 결론을 세 번째로 확정**하고, 향후 용량 확대는 구조 처방과 동반될 때만 허용한다.
- 어떤 arm이든 T2를 통과하지 못하면 판정 대상에서 제외한다.
- A3(스펙트럼 손실)이 S3(파워비)만 개선하고 P1·P2를 개선하지 못하면 **"§2.7과 동형의 캘리브레이션-전용 효과"** 로 판정하고 단독 채택하지 않는다 (조합 arm에서만 유지).

**해석 규칙 (사전 고정)**:

- A2가 이기고 A5가 지면 → "분해능 병목은 용량이 아니라 **표현의 분해(decomposition)**"가 확정된다.
- A1이 이기고 A3이 지면 → "고주파 문제는 **경로(architecture)** 문제이지 **가중(loss)** 문제가 아니다".
- A1·A3 모두 지고 A2만 이기면 → "고주파 감쇠는 증상이고, 진짜 원인은 **저주파 프라이어 부재로 인한 용량 낭비**".

### 11.3 설계와 달라진 구현 결정 2건 (기록)

**(a) 맵 잔차를 "타깃 변환"이 아니라 "네트워크 내부 가산 스킵"으로 구현했다.** cyclen처럼 타깃을 `label − prior`로 바꾸면 서빙 시 프라이어를 되더해야 하고 그 코드는 `model_api.py`에 있는데, **타 에이전트가 그 파일을 수정 중이라 건드릴 수 없다**(§5-6 제약). 대신 `map_prior_channel`이 입력 채널의 프라이어 평면을 학습 가능한 per-plane 아핀(gain 초기값 `[1,0,0,0]`, bias 0)으로 맵 헤드 출력에 **더한다**. 손실이 헤드 출력에 주는 그래디언트는 잔차 학습과 동일하고, `out["map"]`은 여전히 **절대값**이므로 **서빙 경로 변경이 0이다**. 초기 상태에서 맵 예측 = 확산 프라이어이므로 워밍 스타트 효과도 그대로다.

**(b) `(M², extrap)`는 train 폴드에서만 적합하는데, 그 폴드의 맵 라벨이 단일 레짐이다.** 스모크 실행에서 train 4,000행 적합이 `M²=60, extrap=2.0 / 셀내 ρ 0.278`을 골랐다 — §3.2 프로브(전 코퍼스, 0.592)보다 낮다. 원인은 선행 보고서 §2.1 그대로다: **학습 맵 라벨이 Dataset A / feed 121 / ebin 5.25 단일 셀 100%**라 셀내 변별 신호 자체가 작다. 이는 결함이 아니라 **누출 규칙을 지킨 대가**이며, `extrap = 2.0`은 두 적합에서 일치한다. **X3(커리큘럼 레짐 맵 harvest)이 이 적합의 질도 함께 올린다**는 추가 근거다.

### 11.4 승격 전 필수 후속 작업 (차단 항목)

**`v6` / `v6_prior` arm이 챔피언으로 승격되려면 `model_api.py`의 서빙 인코더가 `meta["power_prior"]`의 `(M², extrap)`로 재구성돼야 한다.** 현재 서빙 인코더는 `FeatureEncoder(cond_schema=...)`를 프라이어 없이 만들므로 **모듈 기본값 (80, 2.0)** 을 쓴다. 적합값이 기본값과 다르면 `prior_power` 채널이 학습 때와 달라진다(스모크에서 60이 선택됐으므로 실제 위험이다). 값은 이미 `power_prior.json`과 멤버 `meta.json`에 기록돼 있으므로 **2줄 수정**이면 되지만, 동시 편집 충돌 회피 지시에 따라 **본 작업에서는 하지 않았다.** A/B 평가 자체는 train.py 내부 예측 경로를 쓰므로 영향받지 않는다.

### 11.5 발사 실패 1건과 수리 (2026-07-25, 실측)

B1 최초 발사가 `python -m lpopt.remote: error: unrecognized arguments: -- --ensemble 5 ...`로 실패했다.

**원인 (실측 확인)**: `lpopt/remote.py`의 파서는 위치인자가 **둘**이다 — `cmd`(nargs=None)와 `train_args`(`nargs="*"`). argparse는 위치인자를 **가장 이른 기회에 탐욕적으로** 채운다. 따라서 옵션이 두 위치인자 **사이에** 오면(`train --input X -- ...`) `--input` 앞의 슬롯 하나에 **두 위치인자를 모두** 매칭시켜 `train_args`를 빈 리스트로 확정하고, `--` 이후 전량이 갈 곳을 잃어 extras가 된다.

- PowerShell의 `--` 삼킴은 **원인이 아니다.** PS 5.1에서 네이티브 exe로 배열 splatting 시 `--`가 그대로 전달됨을 실측했다(`["--input","lpopt.inp","train","--","--ensemble","5",...]`).
- `push` / `status`는 위치인자가 하나뿐이라 **양쪽 순서 모두 정상 파싱**된다. **`train`만 깨진다.**
- **`lpopt/model/al_retrain.py:remote_invocation`도 같은 깨진 순서를 생성하고 있었다**(재학습 계획서에 인쇄되는 문자열). 함께 수리했다.

**수리**: 래퍼 옵션을 서브커맨드 **앞**으로 — `python -m lpopt.remote --input <deck> train -- <train args>`. 전 7 arm을 **실제 두 파서(`lpopt.remote` + `lpopt.model.train`)에 통과시켜 검증**했고, 회귀 테스트 `tests/test_al_retrain.py::test_remote_invocation_actually_parses`를 추가했다(문자열 모양이 아니라 **실제 파싱**을 검사한다 — 기존 테스트는 모양만 봐서 이 버그를 놓쳤다).

**GPU 기본값도 `auto` → `0`으로 고정**했다. 사전점검 중 타 사용자 작업이 끝나 `auto`가 GPU 1을 고르는 것을 목격했는데, 이는 "GPU 0 고정" 지시에 반한다. `-Gpu 1`은 명시적으로만 선택된다.

### 13.4 승자 선정 → 승격 자동화

`lpopt/model/ab_decide.py` 신설. §7 사전등록 규칙을 **코드로 그대로 옮겼다**:

1. 1차: fold C `Δ₇₅/SD`가 **B1 대비 node_peak 또는 map_CoV에서 ≥0.15 개선** + **어느 타깃도 0.05 초과 악화 없음**
2. 3차: 정직 게이트 PASS
3. 2차: cyclen·F_r 셀내 ρ가 B0 대비 −0.02 미만 하락 없음

**동률은 침묵하지 않는다.** 상위 2개 arm의 1차 지표 차이가 0.05 미만이면 판정을 `escalate`로 내고 사람에게 넘긴다 — 사후 타이브레이크는 사전등록을 무효화하기 때문이다. 판정 상태는 `blocked`(대조군 미채점) / `incomplete`(일부 미채점, 잠정 선두만 보고) / `no_winner` / `escalate` / `winner` 5종.

**A5 용량 조항은 승패와 무관하게 항상 보고**된다 — "파라미터를 그냥 키우면 되는가"에 대한 사전등록된 답이기 때문이다.

승격은 **재구현하지 않고** 기존의 검증된 `lpopt gate-promote`(정직 무회귀 게이트 + 레거시 고주기 tail 게이트, 둘 다 통과할 때만 덱·state 포인터 원자 교체)를 호출한다.

```
python -m lpopt.model.ab_decide              # 판정만
python -m lpopt.model.ab_decide --promote    # winner 판정 시 gate-promote까지
```

### 13.5 서빙 블로커 해소 (§11.4 차단 항목)

`model_api.py`의 `PosValCnnBackend`가 이제 **`meta["power_prior"]`의 (M², extrap)로 서빙 인코더를 재구성**한다. 기존 `cond_schema` 일관성 검사와 동일한 패턴이다 — 앙상블 내 상수 불일치는 하드 에러, 필드가 없는 v2~v5 체크포인트는 `None`을 받아 **기존 경로 그대로**다.

이 수리가 없으면 v6 챔피언은 학습 때 `M²=60`으로 만든 `prior_power` 채널을 **서빙 시 기본값 80으로** 만들어 조용히 어긋난다(7열 출력에는 드러나지 않는다). σ 보정 에이전트와의 충돌은 없었다(해당 파일 최종 수정 04:07, 본 수리 06:4x). `ab_decide`는 안전장치로 **v6 승자에게 여전히 `serving_blocker`를 표시**하며, 이 필드가 있으면 `--promote`가 발사되지 않는다 — 수리 여부를 사람이 확인한 뒤 해제해야 한다.

### 14.8 다음 세대 제안 — A2 강화가 1순위

**근거**: A2는 1차 지표(Δ₇₅/SD)는 못 넘겼지만 **파라미터 +6,298개**로 축소편향(SD비 0.554→**0.769**)과 나이퀴스트 파워비(0.451→**0.774**)에서 **단독 최대 기여**를 냈다. 파라미터당 효율이 압도적이고, A6의 우승도 이 기여를 포함한 결과다. 프라이어의 **품질**을 올리면 그 기여가 그대로 커진다.

| # | 처방 | 근거 | 재료 |
|---|---|---|---|
| **N1** | **2군 확산 프라이어** (현재 1군) | 현 프라이어는 균일 D·Σa의 1군 조격자다. 열/속중성자 분리는 반사체 인접 집합체와 Gd 함유 집합체의 출력을 크게 바꾸는데, 지금은 전부 잔차로 떠넘긴다. 프라이어 셀내 ρ 0.44~0.59 → 상승 여지 | 이미 harvest된 `xs_a2`/`xs_nf2`/`xs_s12`/`adf_corner_g2` (cond_v4 채널로 존재) |
| **N2** | **축방향 프라이어** | §1.3 X1이 수확 개시됨. 현 프라이어는 radial 전용이라 축방향 효과가 전부 잔차다. 축방향 라벨이 생기면 **맵 헤드 출력 해상도 자체를 처음으로 늘릴 수 있다**(69슬롯 → 69×25) — §1.4에서 "오늘 라벨로는 불가능"이라 판정했던 축이 열린다 | **지금 수확 중인 EDIT6 25평면** |
| **N3** | 프라이어 상수의 셀별/레짐별 적합 | 현재 (M², ex)는 전역 2개. 다만 셀별로 가면 누출 위험이 생기므로 **train 폴드 내 레짐별**로만 | 기존 |
| N4 | 프라이어 적합 표본 확대 | 현 적합은 train 맵 4,000행이고 그 폴드가 A/feed121/ebin5.25 단일 레짐이라 셀내 ρ 0.278에 그친다(§11.3b). X3(커리큘럼 레짐 맵) 수확이 이 적합의 질을 직접 올린다 | X3 |

**N2가 전략적으로 가장 크다**: 축방향 라벨은 (ⅰ) A2 프라이어를 3-D로 확장하고, (ⅱ) `ao_abs`(현재 "측정 불가") 를 되살리며, (ⅲ) **라벨 해상도 상한 자체를 25배 올린다**. 사용자 목표 "분해능을 늘려라"에 대해 모델 구조가 아니라 **데이터 축에서** 답하는 유일한 경로다.

### 14.9 미해결 후속 (코디네이터 판단 필요)

1. **`lpopt.inp` `[model] cond_schema = "v5"`가 그대로다.** 이 키는 서빙이 아니라 **커리큘럼 재학습**이 쓰는 값이다(`curriculum.py:1548,1576`). 챔피언이 v6이 된 지금, 다음 커리큘럼 재학습은 v5 모델을 만들어 **A6 구조를 잃는다.** `config.py:361` 주석이 "A/B가 승자를 정한 뒤에 올리라"고 명시한 항목이므로 지금이 그 시점이다. 다만 **커리큘럼이 `--map-decoder`/`--map-prior-residual`/`--map-spectral-weight`를 전달하지 않으므로**, 스키마만 v6으로 올리면 선형 맵헤드 v6 모델이 나온다 — 커리큘럼 재학습 인자에 A6 레시피를 함께 실어야 완결된다.
2. **`gate-promote`에 dry-run이 없다.** PASS 즉시 무조건 승격한다(`cli.py:1536-1545`, `--promote` 플래그 자체가 없음). 게이트만 보고 싶을 때 안전장치가 없으므로 `--check-only` 추가를 권한다.
