## 1. 사용자 비전의 물리적 번역

### 1.1 "17x17"의 두 가지 읽기 — 둘 다 짚는다

현 스택에서 두 숫자가 모두 실재한다.

* **집합체 격자**: 16×16 CE형 (236 연료봉 + 20 안내관). 근거 —
  `design/coredeck.py:_gen_pin_edt` `npin=16, nfrod=236`; HGC `%DIST` 맵이 16×16
  (`data/fuel_types.py:_first_dist_map_flat`); dbx 1/8 핀맵 주석 "16x16 CE assembly:
  236 fuel rods + 20 guide-tube cells".
* **노심 집합체 격자**: 17×17 (241 FA). 근거 — `model/power_prior.py:_CORE = 17`,
  `data/flatness.py:_CORE = 17`, `featurize._CORE = 17`.

사용자 문장이 "다양한 크기의 **노심**"으로 이어지므로 **작동하는 읽기는 후자**(노심 격자)다.
그러나 전자도 짚어 둘 값이 있다: **집합체 격자 축은 이미 불가지화되어 있다.** v5에서
독봉 특정 채널(n_gd, gd_wt, gd_u_enr)을 제거하고 k-conv 곡선형상 8채널로 대체한 것이
정확히 "격자 설계가 아니라 격자 **거동**을 본다"는 결정이었다
(`featurize._V5_DROPPED_CHANNELS`, `_V5_SHAPE_EXTRA`; 사용자 지시 2026-07-20).
`pin_pitch/asm_pitch/r_pellet/r_clad_*/p_over_d/v_mod_over_v_fuel`는 수확은 되어 있으나
**채널이 아니다**(`GEOM_COLUMNS`, 48/194 커버리지) — 의도적이다. 현 학습 격자 전체에서
상수이기 때문이고, OOD 가드용 부기로만 존재한다.

> **따라서 v3는 "집합체 지오메트리 → 출력"으로의 전환이 아니다. 그 전환은 2026-07-18/20에
> 이미 등록·시행되었다. v3가 추가하는 것은 오직 "노심 크기 불가지 + 누설 해석"이다.**
> 이 프레이밍이 중요한 이유: 범위가 훨씬 작아지고, 이미 검증된 것(전이 명제)을 다시
> 검증하는 낭비를 막는다.

### 1.2 "빠르게 최적 노심 도출" = 이미 있는 실행 골격

`autoeng.py`(자동 엔지니어)가 그 골격이다. 셀 단위 순차 루프
`0 PRECHECK → 1 PROBE → 2 OPEN → 3 HARVEST+MERGE → 4 RETRAIN+GATE → 5 MAP UPDATE → 6 NEXT`,
전 단계가 이미 검증된 조각의 **합성**이고 새 알고리즘이 없다는 것을 파일 헤더가 표로 선언한다.
v3 모델은 이 골격의 **4단계(모델)만 교체**하는 플러그인이어야 하며, 골격 자체를 바꾸면 안 된다.
`autoeng`의 세 가지 자체 기여(프리레지 자동화 / append-only 상태로그 / 설정 게이트)는
플랜트가 늘어나도 그대로 쓴다.

### 2.2 노심 인코더: 이미 대부분 크기 불가지다 — 이것이 이 문서의 핵심 실사

`model/net.py::PosValNet.forward`를 한 줄씩 크기 의존성으로 분해하면:

| 구성 | 크기 의존? | 근거 |
|---|---|---|
| `stem` = Conv2d(58→224, 3×3, pad 1) | **아니오** | 순수 합성곱 |
| `blocks` = 8 × ResidualBlock(3×3 ×2) | **아니오** | 순수 합성곱 |
| `films` = FiLM(13 globals → per-channel scale/shift) | **아니오** | 채널별, 공간 무관 |
| `masked_mean = (h*fuel_mask).sum(2,3) / fuel_mask.sum(2,3)` | **아니오** | **마스크 합으로 정규화**되어 있음 |
| `masked_max` | **아니오** | 마스크 후 amax |
| `head_trunk / mu / log_sigma / conv / quantile` | **아니오** | 풀링 결과가 `2W + n_globals`로 고정 |
| `_map_quarter`의 `gather → scatter` | **예** | `_se_r/_se_c/_q_r/_q_c` 버퍼가 `SLOTS`+`_GRID_CENTER=9`에서 고정 생성, `_QUARTER=9` |
| `map_prior_channel = 50` | 아니오 (채널 인덱스) | 채널 목록이 같으면 유효 |

> **즉 트렁크와 전역 헤드는 오늘 이미 임의 크기 격자에서 동작한다.**
> `forward`가 19나 9를 읽는 곳은 `_map_quarter` **한 군데뿐**이고, 그것은
> **파라미터가 없는 인덱싱 연산**이다.

수용영역도 확인해 두자. 8 블록 × 블록당 2개의 3×3 conv = 16 conv → 반경 16 → **33×33**.
목표 노형 중 **APR1400(17×17)이 가장 크다**(OPR1000·i-SMR은 더 작다). 따라서 현재 트렁크의
수용영역은 이미 **전 목표 노형에서 전역(global)** 이다. 이것이 §4 판정의 결정적 근거다.

### 2.3 기하는 이미 **단일 원천**에서 파생된다

`vendor/masterrl/domain.py:20`

```python
ROW_LENGTHS: tuple[int, ...] = (9, 9, 9, 9, 8, 8, 7, 6, 4)   #  ← 이 튜플 하나
```

`_build_slots()`가 여기서 69개 `Slot(index,row,col,multiplicity,orbit_class,radius)`를 만들고
`sum(multiplicity) == 241`을 자체 검증한다. 그리고 **나머지 전부가 `SLOTS`에서 파생된다**:

* `featurize._build_scatter()` → `_POS_ROWS/_POS_COLS/_POS_SLOT/_FUEL_MASK/_REFLECTOR_MASK`
* `flatness._core_geometry()` → `_CORE_MASK/_SLOT_OF/NEIGH_SLOT/PERIPHERY_MASK/SLOT_WEIGHTS`
* `power_prior._core_geometry()` → `CORE_MASK/SLOT_OF/NODE_INDEX/N_NODES=241/NODE_SLOT`
* `power_prior._operator()` → 확산 유한차분 행렬 A (마스크에서 직접 조립)
* `net._slot_indices()` → 맵헤드 gather/scatter 버퍼
* `edit5._MAP_SIDE = len(ROW_LENGTHS)` → 라벨 맵 레이아웃
* `genome.py` / `vendor/ga.py` → 궤도단위(ORBIT_UNITS) 60개, `feed = 1+4N`

**`ROW_LENGTHS`를 참조하는 파일은 4개, `SLOTS`를 import하는 파일은 16개.** 즉 크기 결합은
**넓지만 얕다** — 한 곳을 객체로 만들면 나머지는 그 객체를 받는다.

### 2.4 누설은 이미 세 곳에 있다 (다만 전부 APR1400 상수)

| 위치 | 형태 | 현재 값 | 크기 의존성 |
|---|---|---|---|
| `model/power_prior._operator` | 외곽면마다 대각에 `+1/extrap` 추가 = 외삽경계 | `extrap = 2.0`, `M² = 150.0 cm²` (s1g 적합, within-cell ρ 0.689) | 마스크에서 자동 — **구조적으로는 이미 크기 반응적**, 두 스칼라만 적합 |
| `model/physics_prior` | 0차원 반응도 수지의 lumped 누설항 `B_cycle=(ρ̄−RHO_LEAK)/D` | `RHO_LEAK_PCM = 3500.0` (전역 상수), s1g `alpha=10.3297 beta=602.20 pearson 0.872 spearman 0.886 n_fit 53,236` | **없음. 하드코딩 스칼라** |
| `opmodel/opmodel.py` (보정 LRM) | 임계 문턱 `rho*` | `RHO_STAR = 0.0168`, `w_B = 5.348 pcm/ppm`, `RATE = 3983/104.8/1000`, `NSLOT = 241` | **없음. 플랜트 상수 4개** |

`power_prior`의 확산 솔버는 **이미 마스크 일반적**이다 —
`_operator()`가 `CORE_MASK`를 순회하며 "연료가 아닌 이웃 = 외곽면"으로 판정해 `1/extrap`을
더한다. 마스크가 바뀌면 누설이 자동으로 따라온다. 막는 것은 `_CORE=17 / _CORE_CENTER=8 /
PITCH_CM=20.78` 세 상수뿐이다.

**이것이 §5 설계의 출발점이다: 누설 기계는 이미 있고, 크기 파라미터가 없을 뿐이다.**

**v3에 직접 관계있는 세 가지**

1. **모델에게 요구하는 것**이 명시되어 있다 — 프리레지가 MASTER 콜 한 번 나가기 전에

   게이트 값**이 되어, 헤더를 고치면 해시가 바뀌고 발사기가 거부한다.
   → **v3 모델은 이 세 산출(`min_pred_f_r`, `bias_tail`, `corrected_floor`)을 그대로 내야 한다.**
2. **5단계(그물망 갱신)가 조건부**인 이유가 측정값이다 — 스토어만 +100행 늘었을 때
   `min_pred_f_r` 평균 이동 **−0.0036**, **55셀 중 52셀이 비트 동일**.
   *"이건 노브가 아니라 측정된 의존관계다."*
3. **v1 한계 (그대로 물려받는다)** — 원격 레그(199/238 ssh·scp·폴링)는 배선만 되고
   **한 번도 실제 실행된 적이 없다**; 새 집합체는 precheck 후 정지; **핀연소도는 게이트되지 않는다**
   (`min_fr_max_cycle`에 핀연소도 축이 없다 — precheck는 경고만 하고 막지 않는다);
   드라이버 레벨 락이 없다.

**v3 모델은 4단계 아티팩트 계약(챔피언 포인터 = `data/curriculum/state.json`)만 지키면
그대로 꽂힌다.** 새 플랜트는 `[[targets]]` 항목에 `plant` 키가 하나 늘어나는 형태여야 한다

## 3. 갭 인벤토리 — 사용자 목록 대조

각 갭에 대해 **출처 / 종류(featurizer 추가 vs 격자체인 추가) / 비용 / 우선순위**를 적는다.
"격자체인 추가"는 DeCART2D를 새로 돌려야 한다는 뜻이고, "featurizer 추가"는
이미 디스크에 있는 산출물을 더 읽는다는 뜻이다 — **비용 차이가 두 자리수다.**

### 3.1 k-curve — ✅ 있음 (압축됨). **확대 금지 권고**

* **현재**: `kinf0/10/20/30` 4점 + `bu_k1` + k-conv 형상 9개(dip/peak/swing/slope/eol50/monotone).
* **원천**: `.sum` SUMMARY EDIT2 (K-CONV 열) / HGC `%TITL` 상태별 k-inf.
  그리고 **`config/fuel_types_dbx_extracted.yaml`에 62점 격자의 k∞(BU) 전곡선이 40개 타입에
  이미 파싱되어 있다** (`burnup_grid_gwd_per_tu`, 0→80 GWd/tU, 20개 시트, 파싱실패 0).
* **종류**: featurizer (원천은 이미 디스크).
* **판정**: **지금 확대하지 마라.** `kcurve_fusion_memo_20260809.md` §3(0) 실측
  (`featurize.py:50-56`에 인용되어 있는 형태 그대로): 연소슬롯 배치오차 평균 **12.18 GWd/tU
  = 노심평균 반응도 2,801 pcm**이고 이는 **k곡선 4스칼라 압축오차의 5.1배**이며,
  코어의 45.8 %에서 연료교체 한 번의 효과를 넘는다. v6b가 후자를 고쳐 게이트를 통과했다
  (node_peak 셀중앙 MAE +0.01734 = 기준 0.00409의 4.2배).
  곡선 정밀화는 **5배 더 작은 오차원을 쫓는 일**로 이미 정량 판정났다.
* **v3에서의 역할**: 62점 곡선은 **채널이 아니라 opmodel/LRM의 입력**으로 쓴다(§8 Stage-1).
  LRM은 곡선 전체를 먹고, CNN은 압축본을 먹는다 — 각자 강한 곳에.

### 3.2 Fr / Fq 집합체 기여 — ⚠️ 부분. **FF(BU) 전곡선이 미수확**

* **현재**: `ff_pin_max` = BOC 핀 form-function 최대치 **스칼라 1개** (158/194 커버리지).
  노심 F_r·F_q는 타깃(8타깃 중 2개). 핀연소도 곡선은 `pin_bu_r_inf/paramA/ratio_asym`으로
  요약되어 있고 서브모델(`model/pinbu_physics.py`)이 있다.
* **누락**: **FF(BU) 전곡선.** dbx yaml이 62점 격자에서 k∞와 **나란히 FF(BU)를 담고 있다.**
  `.sum` EDIT3의 `FRP` 열도 상태별로 있다(현 파서는 BU=0 행 하나만 읽음:
  `fuel_types.parse_fa_sum` → `if toks[0] == "1"`).
* **왜 중요한가**: 노심 F_q = (노드 출력) × (그 노드 집합체의 그 시점 FF). BOC FF만으로는
  **연소가 진행되며 FF가 평탄화되는 경로**를 볼 수 없다. `kcurve_fusion_memo`가 이미
  "F_r 외곽 루프는 궤적 융합 `max(p·FF(BU))`로"를 처방했다.
* **종류**: **featurizer 추가** (dbx yaml 파싱 + `.sum` EDIT3 전행 파싱). 격자 재계산 불필요.
* **비용**: 파서 확장 ~150 LOC + 채널 3–4개 (`ff_at_bu20`, `ff_slope`, `ff_asym`, present gate).
* **우선순위**: **중** — Stage-1 이후, F_q가 실제로 게이트를 무는 셀이 나오면.
  지금 F_q는 F_r보다 여유가 크다.

### 3.3 MTC / FTC — ⚠️ **집합체는 있고, 노심 라벨은 0개**

* **집합체 수준 (있음)**: `mtc_dmod` (pcm per 0.01 g/cc, DMOD1..6 분지의 최소자승 기울기),
  `doppler_coef` (pcm/K, TFUEL 분지), `boron_worth` (pcm/ppm), `cr1_worth` (pcm).
  전부 채널 (`origin_mtc_dmod` `origin_doppler` `origin_boron_worth` `origin_cr1_worth`),
  158/194 커버리지. 출처 = `.sum` EDIT1 CASE 라벨 + EDIT2 반응도 표, 또는 HGC `CASE ::`.
* **노심 수준 (없음)**: `search/sdm_mtc.py`가 plan §12.5 하네스로 **완전히 구현되어 있다** —
  `%EXE_RHO`/`%EXE_ROD`/`%ROD_CFG`/`%ROD_MAP` 분지 덱 합성, 후보당 **약 2 MASTER 콜**
  (평형 연소체인 아님, 20–60초 정상상태), MOCHA 감사 F1 수정(배율 휴리스틱 제거) 반영,
  DCD 창 `MTC ∈ [−54, +9] pcm/°C`, `SDM required = 10180+690 = 10870 pcm`.
  결과는 사이드카 `data/sdm_mtc/results.jsonl`. **그런데 그 디렉터리가 존재하지 않는다 → 라벨 0개.**
* **종류**: 라벨 생산 (MASTER). featurizer 작업 아님.
* **판정**: **MTC/FTC를 v3에서 예측 타깃으로 승격하지 마라** (§9-5). 하네스만 있고 라벨이 없는데
  헤드를 다는 것은 v6c face-ADF 실패의 재연이다. 먼저 캠페인 후검증에서 라벨을 쌓아라
  (후보당 2콜이면 100콜 캠페인당 top-K 20개 = 40콜 = 40 % 오버헤드; **top-5만 하면 10콜 = 10 %**).
* **크기 불가지 관점의 의미**: MTC는 **감속재 온도계수**이므로 노심 크기가 아니라 감속재 비율과
  붕소농도에 붙는다. 즉 **집합체 채널로 이미 충분히 표현**되고, 크기 축의 갭이 아니다.
  FTC(도플러)는 더더욱 집합체 국소량이다. **사용자 목록에서 이 둘은 "이미 됐다"에 가깝다.**

### 3.4 핵종 인벤토리 — ⚠️ **원천 완비, 의도적 미수확. 지금 채널화 금지**

* **원천 (확인)**: `0_APR1400/0_MOCHA/FA/IGD_16/6_16_z1/FA_A01.out` 27 MB, `ISOTOPE INVENTORY`
  블록 **334개** (= 상태 수), 각 블록에 **핀별 39핵종 MASS(g)** 표:
  `90232 91233 92233 92234 92235 92236 92238 93237 93239 94238 94239 94240 94241 94242
  95241 95342 95243 96242 96244 64152 64154 64155 64156 64157 64158 64160 68166 68167
  68168 68170 5010 60647 61647 61748 61649 62649 53635 54635 1001` — U/Pu/Am/Cm 전 사슬 +
  Gd 6동위체 + Er 4동위체 + B-10 + Sm/Xe/I.
* **현 파서**: `parse_fa_mass_out`이 **BURNUP=0 블록의 TOTAL 행에서 92235/92238 두 개만** 읽어
  `u_avg_enrichment`/`u_mass_g`를 만든다. 나머지 39×334×256은 버려진다.

  (b) 4주기 이상 체류에서 Pu 축적이 k(BU) 곡선으로 안 잡힌다는 **실측 증거가 나올 때**.
  지금은 **"원천이 있다"는 사실만 이 문서에 기록**한다.

### 3.5 소수군 상수 / 이주면적 — ⚠️ **부분. 여기가 진짜 지렛대다**

* **현재 채널**: `origin_xs_a2` (2군 Σa), `origin_xs_nf2` (2군 νΣf), `origin_xs_s12` (1→2 산란).
* **테이블에는 있으나 채널이 아닌 것**: `xs_d1`, `xs_d2`, `xs_a1`, `xs_nf1` (전부 158/194 수확됨).
* **왜 중요한가**: **이주면적 M² = D/Σa** 가 누설의 물리적 스케일이다. 현재
  `power_prior`는 **전역 M² 하나를 격자탐색으로 적합**한다 (`DEFAULT_GRID` = 6 M² × 3 extrap,
  s1g 선택값 150 cm²). 그런데 `xs_d1/xs_a1/xs_d2/xs_a2`가 이미 있으므로
  **집합체별 M²를 계산할 수 있다.** 그러면:
  * 확산 솔버가 균질 M² 가정을 버리고 **국소 M²(j)** 로 풀 수 있다 (`_operator`의 `gamma`가
    노드별이 되면 됨 — 행렬 조립 코드는 그대로);
  * **적합 상수가 하나 줄고**, 그 상수는 새 플랜트에서 재적합이 필요한 바로 그 종류의 것이다.
* **종류**: featurizer + 프라이어 수정. 격자 재계산 불필요. 채널 4개 추가 (append-only).
* **우선순위**: **최상 (Stage-1 중심 항목).** 이것이 "누설을 해석한다"는 사용자 요구의
  가장 직접적인 물리 구현이고, 동시에 플랜트 간 전이를 **공짜로** 만드는 항목이다.
* **반증 가능**: 집합체별 물리 M²가 전역 적합 M²=150보다 **나쁘면**, 수확된 XS의 스케일이
  전이 가능하지 않다는 뜻이고 → 플랜트당 스칼라 2개 적합으로 되돌린다 (비용 낮음).

### 3.6 반사체 / 알베도 / 경계 — ❌ **가장 큰 갭. 정보량이 문자 그대로 0이다**

* **현재**: `reflector_mask` 채널 1개. 그런데 `featurize.encode()`가
  ```python
  grid[self._ch_index["reflector_mask"]] = _REFLECTOR_MASK      # 모듈 상수 배열
  ```
  로 **모든 레코드에 동일한 정적 배열**을 쓴다. 즉 이 채널은 레코드 간 분산이 0이고,
  네트워크에는 "여기가 격자 바깥"이라는 **기하 정보만** 준다. 반사체 물성은 없다.
* **정작 덱에는 있다**: `design/coredeck.py`
  ```python
  REFLECTOR_BATCHES = (("R1", -2), ("R2", -3), ("R3", -4))
  REFLECTOR_COMPS = ((-1,"REF_AXIAL_B"), (-2,"REF_R1"), (-3,"REF_R2"),
                     (-4,"REF_R3"), (-5,"REF_AXIAL_T"))
  ```
  `FULL_BCH_MAP` 19×19 텍스트가 **어느 외곽 위치에 R1/R2/R3 중 무엇이 오는지**를
  집합체 단위로 지정한다 (모서리는 R3, 면은 R1/R2). 즉 **반사체는 3종이고 배치가 비균질한데
  모델은 그것을 이진 1로만 본다.**
* **필요한 것 (§5에서 설계)**: 경계 노드 블록 — 반사체 종류, 군상수 또는 알베도,
  그리고 **연료 노드마다 "바깥을 보는 면의 개수"**.
* **종류**: featurizer 추가. **격자 재계산 불필요, 그리고 파싱 대상이 매우 작다.**
  반사체 군상수는 **`MAS_REF` 텍스트 파일 한 장(2,008 바이트)** 안에 전부 있다:
  `REF_AXIAL_B`/`REF_AXIAL_T`(축) + `REF_R1`/`REF_R2`/`REF_R3`(반경, 각 10개 숫자,
  상태점 500 ppm / 290.6 / 151.32). TotalBatcher는 반사체에 대해 **계산을 하지 않고
  `MAS_XSL` 앞에 바이트 그대로 접합만 한다**(`REFLECTOR_CHAIN.md` §1.1 바이트 검증).
  세 반경 반사체는 실제로 크게 다르다 — 여섯째 값이 R1 `3.60917E-01` · R2 `4.04415E-01` ·
  **R3 `1.17854E+00`**. `design/library.py`의 `refl_count`가 이미 그 블록 수(5)를 센다.
* **우선순위**: **최상 (Stage-1).** 세 최우선 갭 중 원천이 가장 명확하다.

### 3.7 절대 크기 좌표 — ❌ **정규화가 크기를 소거하고 있다**

* `pos_radius = slot.radius / _R_MAX` (`_R_MAX = max(slot.radius for slot in SLOTS)`).
  `chain_source_radius`, `chain_displacement`, `src2_radius`도 전부 `/_R_MAX`.
* **결과**: 17×17 노심과 15×15 노심에서 **같은 상대 위치는 같은 값**이 된다. 그러나 누설은
  `r/M`(이주거리 단위 절대 거리)에 붙지 `r/r_max`에 붙지 않는다. 두 노심의 외곽 집합체는
  상대좌표가 같아도 **누설이 다르다.**
* **필요**: `pos_radius_in_M = radius × pitch_cm / sqrt(M²)` 채널 + 전역
  `core_size_in_M = sqrt(N_full) × pitch / sqrt(M²)`, `surface_to_volume`.
* **종류**: featurizer 추가 (순수 파생, 원천 불필요).
* **우선순위**: **최상 (Stage-1).** 세 최우선 갭 중 가장 싸다.

### 3.8 축방향 — ❌ **i-SMR 한정 v3 차단 갭**

* **이미 있는 것**: `data/axial.py` — EDIT6 1-D 출력분포 파싱, **25 연료노드**, BOTTOM→TOP,
  노심평균 1 정규화(편차 1.95e-4), `axial_offset()`이 MASTER EDIT3 AO를 6e-5로 재현,
  `ANCHORS = ("boc","eoc")`, `AxialBasis` (평균 프로파일 + 영합 형상성분).
  `net.py`에 `n_axial_anchors × n_axial_modes` 헤드가 **구현되어 있다** (`out["axial"]`,
  `basis.z_decode`로 F_z/AO/ASI가 해석적 함수). **챔피언은 0/0 = 꺼짐.**
* **없는 것**: **축방향 장전 자유도 자체.** 현 장전 표현 `Pattern`은 69개 `%LPD_SHF` 카드,

  제어봉 위치는 결정변수가 아니다.
* **사용자 지시 (2026-07-25, 확정)**: *"축방향 자유도 확장 안 함 — 어떤 덱·계획에도 넣지 말 것.
  APR1400급 대형 노심 + 붕산수 반응도 제어에서는 AO가 기준치 한참 아래라 예측 필요성이
  사실상 없음. 소형 노심(i-SMR) + 제어봉 제어로 갈 때 축방향 편차가 커지므로 그때 탑재."*
  실측 근거: 전 코퍼스 |AO|max **0.278 < 제약 0.30**, std ~0.014, 밴드 무관.
* **판정 (v3 범위 결정)**:
  * APR1400 · OPR1000 → 축방향은 **차단 갭이 아니다.** v3에서 다루지 않는다.
  * **i-SMR → 축방향은 차단 갭이다.** 그리고 그것은 채널 추가가 아니라
    **(a) 결정변수 확장 (축방향 장전 + 제어봉 위치), (b) 제어 패러다임 변경 (붕소 → 제어봉),
    (c) 라벨 축 추가 (EDIT6 × 새 플랜트), (d) F_z/AO/ASI의 게이트 타깃 승격**
    네 가지가 동시에 필요한 **별도 프로그램**이다.
* **따라서 §8의 단계 계획은 i-SMR을 Stage-3 이후의 독립 프로그램으로 분리한다.**
  v3를 "APR1400 + OPR1000의 반경방향 크기 불가지"로 정의하고, i-SMR을 그 위에
  얹는 것이 유일하게 정직한 범위 설정이다. **i-SMR을 v3에 접으면 v3가 끝나지 않는다.**

## 4. 아키텍처 판정 — **완전-합성곱 재적합 (경로 하나만 권고)**

### 4.1 권고

> **`ROW_LENGTHS` 상수를 `CoreGeometry` 객체로 승격하고, 8개 모듈이 그 객체를 받게 하고,
> 맵헤드의 고정 gather 버퍼를 배치별 인덱스로 바꾼다. 트렁크·전역헤드·손실·타깃·채널은
> 한 글자도 바꾸지 않는다. GNN을 만들지 않는다.**

### 4.2 근거 — 다섯 가지, 전부 읽은 코드에서 나온다

**(1) 트렁크는 이미 크기 불가지다.** §2.2 표. `forward`가 공간 크기를 읽는 유일한 곳이
`_map_quarter`이고 거기엔 파라미터가 없다. 마스크 정규화 풀링
(`(h*mask).sum(2,3) / mask.sum(2,3)`)이 이미 크기·형상 무관하게 올바른 평균을 낸다.
GNN이 제공한다고 흔히 말하는 "가변 크기 처리"를 **이 네트워크는 이미 갖고 있다.**

**(2) 수용영역이 이미 전역이다.** 16개의 3×3 conv = 33×33 수용영역 ≥ 17×17 (최대 목표 노심).
GNN의 메시지 패싱이 사는 이유(장거리 의존, 임의 위상)가 **여기서는 살 자리가 없다.**
목표 노형 셋 다 정방 피치이고 APR1400보다 작다.

**(3) 기하가 이미 단일 파생 원천이다.** §2.3. 튜플 하나 → `SLOTS` → 나머지 전부.
GNN은 이것을 **버리고** 인접행렬 파이프라인을 새로 만든다. 완전-합성곱 재적합은 이것을
**그대로 승격**한다.

**(4) 파라미터가 보존된다.** 완전-합성곱 재적합은 `state_dict`가 바뀌지 않는다 —
gather 버퍼는 `persistent=False`로 등록되어 있어 체크포인트에 없다
(`net.py:381-384`). 따라서 **s1g 챔피언 10.4M×5 가중치가 그대로 로드된다.**
GNN은 74k행 학습 투자와 11라운드 챔피언 계보를 전부 버린다. 그리고 §2.7의 스케일링 판정이
"현 구조가 무릎점"이라고 했으므로, **다시 벌어야 할 것이 정확히 얼마인지 이미 측정되어 있다** —
싸지 않다.

**(5) 대칭성 문제는 인코더의 문제가 아니다.** 이것이 가장 중요한 논점이므로 절을 나눈다.

### 4.3 대칭성은 **행동공간**의 문제이지 **관측공간**의 문제가 아니다

과제 지시가 "쿼터 대칭이 플랜트마다 다르다(회전 vs 거울), 궤도 다중도 부기가 APR1400 전용"을
GNN 쪽 논거로 들었다. **읽어 보니 그 논거는 인코더에 적용되지 않는다.**

`featurize.encode()`는 69개 쿼터 슬롯을 **`_mirror_positions()`로 전 노심(17×17)으로 미러
확장한 뒤** 19×19에 패딩한다. **CNN은 쿼터를 본 적이 없다. 항상 전 노심을 본다.**
그래서 `net.py` 독스트링이 "the 19x19 grid is the mirror-expanded full core, so a plain
masked mean over the fuel cells is already the orbit-multiplicity-weighted mean"이라고
쓸 수 있는 것이다 — 다중도 가중은 **미러 확장의 부산물**이지 별도 부기가 아니다.

따라서 플랜트별 대칭 차이가 실제로 때리는 곳은:

| 층 | 대칭 의존? | 파일 |
|---|---|---|
| 인코더 (관측) | **아니오** — 전 노심 확장 후 입력 | `featurize.encode` → `net` |
| 라벨 맵 레이아웃 | 예 (쿼터 9×9) | `data/edit5.py`, `net._map_quarter` |
| **제안기 / 유전자 (행동)** | **예** | `search/genome.py`, `vendor/masterrl/ga.py` |
| 덱 작성 | 예 | `design/coredeck.py`, `data/geometry.py` |

즉 **"전 노심으로 특성화한다"는 불변식만 지키면 대칭 차이는 인코더를 통과하지 못한다.**
그리고 그 불변식은 **오늘 이미 지켜지고 있다.**

**그리고 실제 목표 노형에서는 대칭이 아예 같다.** 원 청사진 §5.1이 이미 등록했다 —
*"OPR1000(177 FA)로 확장 시 **동일 반사-1/4 규칙**으로 K≈53"* (§6.1 인용).
즉 APR1400(K=69)과 OPR1000(K≈53)은 **같은 거울 1/4 대칭**을 쓰고, 차이는 `row_lengths`
튜플의 길이뿐이다. 과제 지시가 상정한 "회전 vs 거울" 분기는 **이 두 플랜트 사이에서는
발생하지 않는다.**

> **정직한 단서** — 미러 확장이 곧 다중도 가중이라는 등식은 **거울 대칭에서만** 성립한다.
> 회전 대칭(rot61 캐시키 같은) 플랜트에서는 `_mirror_positions()`를 그 플랜트의 궤도
> 확장으로 바꿔야 한다. 그러나 그것은 **`CoreGeometry` 객체의 메서드 하나**(`expand(slot) →
> [(r,c), ...]`)이고, 다중도는 반환 길이로 자동으로 나온다. 이미 `Slot.multiplicity`와
> `orbit_class`가 그 개념을 들고 있다.

### 4.4 GNN을 **언제** 재검토할지 (트리거 등록)

GNN이 실제로 이기는 조건은 하나뿐이다: **정방 격자가 아닌 노심.** 육각 격자(VVER, SFR),
또는 집합체 크기가 노심 안에서 섞이는 설계. 목표 노형 셋(APR1400/OPR1000/i-SMR)에는 없다.

> **등록 트리거** — 육각격자 또는 이종피치 노형이 범위에 들어오는 시점.
> 그 전에는 GNN을 설계·구현·프로토타이핑하지 않는다. (§9-1)

## 5. 누설 설계 — 사용자가 명시한 항목

### 5.1 현재 모델이 외곽에 대해 **보는 것**

| 채널/양 | 정체 | 정보량 |
|---|---|---|
| `pos_radius` | `radius / r_max` | 상대 위치. **크기 소거됨** |
| `reflector_mask` | 정적 이진 링 | 레코드 간 분산 **0** |
| `prior_power`, `prior_power_contrast` | 확산 프라이어 출력 | **여기에 누설이 들어 있다** (외삽경계 `1/extrap`) |
| `PERIPHERY_MASK` (`flatness.py:127`) | 바깥을 보는 면이 있는 슬롯 | **리포트 전용, 채널 아님** |
| `rm_fresh_periphery` (`rule_metrics.py:346`) | L-01 저누설 교리 지표 | **리포트 전용, 메커니즘 확인·레버 반증됨** |

**실측 물리 (개입 실험, 2026-08-16 확정)**: *신연료 외곽 배치 = 평탄화 이득 + cyclen 지불.*
부호는 확정, 기울기는 미보정. 즉 **누설-평탄도-주기길이 삼각 트레이드오프가 실측으로
존재하는데, 모델 입력에는 그 축이 명시적으로 없다.**

### 5.2 크기 불가지 모델이 **필요로 하는 것**

**(a) 경계 노드 블록** — `reflector_mask` 1채널을 5채널 블록으로.

| 채널 | 정의 | 출처 |
|---|---|---|
| `n_out_faces` | 연료 노드의 4면 중 노심 밖을 보는 면 수 (0/1/2) | `CoreGeometry` 파생 (`_neighbour_gather`가 이미 계산) |
| `refl_kind` | 인접 반사체 종류 R1/R2/R3 (스칼라 또는 one-hot) | `coredeck.FULL_BCH_MAP` (19×19 텍스트) |
| `refl_xs_*` | 반사체 군상수 (→ 알베도 β 또는 유효 외삽길이) | **`MAS_REF` 2,008 B 한 장** — R1/R2/R3 블록당 10개 숫자 |
| `boundary_present` | 존재 게이트 | — |

`n_out_faces` **하나만으로도 국소 표면/체적 비가 눈에 보인다.** 가장 싸고 가장 물리적이다.

**(b) 절대 크기 좌표** — `pos_radius_in_M = radius × pitch / sqrt(M²)`.
누설은 `r/M`에 붙는다. 이것이 **없으면 두 크기의 노심은 인코더에게 같은 노심으로 보인다.**

**(c) 노심 전역** — `g_n_full` (집합체 수), `g_core_size_in_M`, `g_surface_to_volume`.

**(d) 확산 프라이어를 기하 구동으로** — `_operator()`는 이미 마스크에서 A를 조립한다.
`_CORE/_CORE_CENTER/PITCH_CM`을 `CoreGeometry`에서 받게 하면 **새 플랜트의 선도차수 출력맵이
공짜로 나온다.** 나아가 `gamma = pitch²/M²`를 **노드별**로 만들면
(`xs_d2/xs_a2`에서 집합체별 M²) 적합 상수가 하나 사라진다 (§3.5).

**(e) lumped 누설 상수 두 개를 기하 함수로** —
`physics_prior.RHO_LEAK_PCM = 3500` 과 `opmodel.RHO_STAR = 0.0168`.
0차원 수지에서 누설 반응도는 대략 `M²B_g²`이고 `B_g² ≈ (π/H_eff)² + (2.405/R_eff)²`.
즉 **`RHO_LEAK`는 원리적으로 `(M², 노심 반경, 노심 높이)`의 닫힌 함수**다.
Stage-1에서 이것을 상수 대신 함수로 쓰고, APR1400에서 3500 pcm을 **재현하는지**로 검증한다
(자기 정합성 검사 — 새 라벨 0개).

### 5.3 계층 배치 — 무엇을 어디서 다루나

| 물리 | 담당 | 이유 |
|---|---|---|
| 0차원 반응도 수지 + lumped 누설 | `opmodel` (보정 LRM) | **크기 불가지가 대수적으로 보장됨** (§6.2) |
| 선도차수 공간 출력 + 경계 누설 | `power_prior` 확산 솔버 | 마스크 구동, 이미 일반적 |
| 나머지 (셔플 기하, 스펙트럼, 재분배) | CNN 잔차 | 프라이어가 못 하는 것만 |

이 3계층 분해는 **새로 만드는 것이 아니다** — 오늘 이미 그렇게 되어 있다
(`map_prior_channel=50`으로 맵헤드가 확산 프라이어의 **잔차**를 배우고,
cyclen 헤드가 `physics_prior`의 **잔차**를 배운다). v3는 각 층에 **크기 파라미터를 넣을 뿐**이다.

### 6.2 비용이 **낮은** 쪽: LRM 백본 — **구조는 공짜로 전이하고, 보정은 전이하지 않는다**

`opmodel/opmodel.py` 전체에서 플랜트 의존 상수는 **정확히 네 개**다.

```python
RATE     = 3983.0 / 104.8 / 1000.0   # P_th[MW] / M_HM[MTU] / 1000  → MWd/kgHM per EFPD
NSLOT    = 241                        # 전노심 집합체 수
RHO_STAR = 0.0168                     # 임계 문턱 (누설 + 제어 여유)
w_B      = 5.348 pcm/ppm              # 미분 붕소가 (measured.py 적합)
```

나머지는 전부 대수다 — `residence(feed) = NSLOT/feed`, `Bc = 2·B1/(n+1)` (variant `B1`)
또는 이산 평형 EOC 임계(variant `EOC`), `CBC = (ρ_op,peak − ρ*)/w_B`, `B_d = n·B_c`.
집합체 입력은 **k(BU) 곡선뿐**이다 (BU ≥ 0.2, Xe-free BU=0점 제거).

**APR1400 검증 실적** (`OPSCREEN` §2, feed 117+121, n=55):
cyclen bias +0.05 / **rms 4.26 EFPD (0.66 %)** / max 12.3 EFPD;
CBC (≤1900 ppm 영역, n=53) bias +7 / **rms 37 ppm** / max 86 ppm.

> **따라서 OPR1000 LRM의 골격은 `NSLOT=177`, `RATE = P_th/M_HM/1000`을 넣으면 곧바로 선다.**
> **이것이 크로스-사이즈 정합성 검사의 백본이 되는 이유다: MASTER 0콜로 구조 검사를 먼저 통과시킬 수 있다.**

**그러나 "대수만으로 전이한다"는 과장이다 — 6,113 코어 실측이 그것을 반증했다.**
`dbx_lrm_fit_20260816.md`(feasible DB 전수 6,113 코어)의 잔차:

|---|---|---:|---:|---:|
| **A 해석적 LRM** | `EFPD = 2·B₁(e)/((n+1)·spr)` | 2 | **4.061** | 7.70 |
| **B feed 보정** | `EFPD = α_F·(a + b·e)` | 7 | **2.364** | 4.68 |

| *바닥* 셀×pair 평균 | 포화 | 89+ | 1.678 | 3.34 |

**세 가지 실측 결론 — v3 설계에 직접 들어간다.**

1. **해석적 `2/(n+1)`은 쓰면 안 된다.** 리포트의 축어: *"외곽루프 스크리닝에 쓰는 어떤
   백본도 해석적 `2/(n+1)` 대신 **자유 per-feed 인자**를 실어야 한다. 이것이 이 리포트에서
   **가장 전이 가능한 결과**다."* LRM 예측을 f109 기준으로 정규화하면 관측 대비
   f101 **+1.55 %**, f121 **+1.81 %** — *"해석적 법칙은 너무 넓다."*
   유효 노심크기 자유화(`N_eff` 격자 스캔 최저 250.5, rms 4.048)도, n의 다항식(rms 2.806)도,
   실제 62점 곡선 위 k∞ 평형해(rms 8.04 @ `k_crit=1.0134`)도 **전부 실패**했다.
2. **`bu_k1`이 농축도보다 나은 연료 기술자다.** 같은 파라미터 수로 rms 9 % 감소.
   `k_crit`을 자유화하면 **1.000을 회수**한다 → *"LRM의 단일배치 연소도 능력이 곧 `bu_k1`이다."*
   모델 D는 두 기술자가 **중복이 아님**을 보인다(추가 9 %) — 농축도는 핵분열성 재고,
   `bu_k1`은 Gd 설계와 zoning을 나른다.
3. **f109 능선** — feed 109가 다른 다섯 feed를 지나는 어떤 매끈한 곡선보다 ~1.3 %(≈8 EFPD)
   **위**에 있고, 20개 pair 중 **19개에서** 그렇다. 배치 나머지·`ncyc`·평형/캠페인 혼합
   어느 것으로도 설명되지 않는다.

> **v3에 대한 함의 (수정된 §6.2 결론)** — 새 플랜트의 LRM 백본은
> `(NSLOT, RATE)` 두 개를 **넣고**, `(a, b)` + **feed 열당 자유 인자 α_F**를 **적합**해야 한다.
> 즉 재적합 자유도는 2개가 아니라 **2 + (feed 열 수)** 이고, 열당 3–5 실측점이면
> 6열 기준 **18–30 평형 노심**이다. 그 자료는 Stage-2가 어차피 만든다.
> **그리고 이 사실 자체가 크로스-사이즈 정합성 검사를 더 중요하게 만든다** —
> α_F가 왜 해석적 형태에서 벗어나는지 우리는 **모르므로**, 새 플랜트에서 그것이
> 어떻게 벗어나는지도 예측할 수 없다. 검사는 **정확도**가 아니라 **구조**
> (단조·평활·질량수지 항등식·누설 부호)만 통과시켜야 한다.

**정직하게** — LRM 골격의 잔차는 `opmodel`에서 rms 4.26 EFPD (n=55, feed 117+121),
dbx 해석형에서 4.06 EFPD (n=6,113) — **프로그램 수용바(≤1 EFPD)에 못 미친다.**
LRM의 역할은 최적점 예측이 아니라 **설계공간 형상 제시와 크기 축 구조 검사**다.
(`reloadmap_methodology_20260816.md` §3.1/P1이 이 구분을 명시적으로 등록했다.)

**추가 등록 주의 (dbx §7)** — 서로게이트의 `ceil_cyclen`은 DB 발자국 안(e5.1–5.5)에서
**상한이 아니다**: 30셀 중 **24셀에서 실측 최대 EFPD가 그것을 넘는다**(평균 −8.2 EFPD,
최악 −22.5 @ `e5.3_f109`). 그리고 **e6.0 행 전체가 그물망 자체의 불연속**이다
(e5.9→e6.0가 +38…+43 EFPD, LRM 기대의 ~3.5배) — **MASTER 앵커 없이 읽지 말 것.**

   **여기가 좋은 소식이다**: `fuel_types.py`의 파서는 **플랜트 무관**이다. DeCART 격자 산출물의
   형식만 맞으면 어느 플랜트 집합체든 같은 158개 컬럼으로 수확된다.

**첫 셀 체인수 견적** — 이 리포지토리의 실측 케이던스로:
* 블라인드 전이 프로브: **8콜** (plan §12.3 blind probe, `autoeng` probe_budget)
* 셀 개통 캠페인: **100콜** (f113에서 41 feasible / 100콜, 첫 feasible 23콜째 — 검증된 예산)
* LRM 백본 앵커: **feed 열당 3–5점 × 열 수** (§6.2 수정판; 6열이면 18–30콜)
* **→ 첫 셀 ≈ 108콜 + 앵커, 첫 플랜트 미니그리드 3셀 ≈ 350–380콜.**

> **⚠ 이 견적을 낙관으로 읽지 마라 (autoeng 설계문서 §9 한계 #3).**
> *"OPEN 레시피는 한 셀의 증거이지 법칙이 아니다"* — f113의 41/100은 **교차-feed 엘리트 부모
> 26개를 가진 셀**에서 나왔다. **완전히 새로운 플랜트에는 엘리트 부모가 0개다.**
> `elite_perturb` 생성기는 부모를 못 찾으면 `random`으로 강등되며 그 사실을 크게 보고한다.
> 따라서 새 플랜트의 첫 셀은 **랜덤/휴리스틱 DoE만으로 시작**하고, feasible 수율은
> f113보다 낮게 잡아야 한다. **첫 셀 예산을 100이 아니라 150–200으로 사전등록하고,
> "첫 셀은 개통이 아니라 부모 풀 부트스트랩"이라고 목표를 다시 쓰는 것이 정직하다.**

**핵심 판단** — 항목 1·2가 v3 프로그램의 **범위 밖**이다. 이것은 모델 작업이 아니라
노심해석 자산 작업이고, 그것을 v3의 일정 안에 넣으면 **Stage-2가 자산 구축에 잡아먹힌다.**

**그래서 §10-2에 대안을 올린다: "합성 축소 노심".**
`CoreGeometry`의 `row_lengths`를 잘라 APR1400 마스크에서 **15×15 / 177 FA급 가상 노심**을
만들고, **같은 ga80/paramA 연료·같은 반사체 XS**로 MASTER 덱을 합성해 라벨을 생산한다.
* **얻는 것**: G2-a(제로샷 전이)의 **인코더 층위 명제를 그대로 검사**할 수 있다 —
  "같은 집합체, 다른 크기 노심에서 순위지식이 전이하는가"는 **크기가 다르기만 하면**
  물어볼 수 있는 질문이다. 그리고 §6.3의 "엘리트 부모 0개" 문제도 완화된다
  (APR1400 패턴을 축소 사영해 부모로 쓸 수 있다).
* **잃는 것**: 실제 OPR1000의 집합체 설계·운전조건·반사체가 아니므로 **물리적 대표성이 없다.**
  "OPR1000에서 된다"는 주장은 **할 수 없다.**
* **정직성 조건**: 문서·프리레지·그림에 **반드시 "합성"이라고 명시**한다. 그러면 이것은
  거짓이 아니라 **범위가 좁은 참**이 된다 (이 프로그램이 `batch_swap` 1.4605를
  "off-series 주석"으로 그린 것과 같은 규율).

**권고** — **Stage-2를 두 갈래로 사전등록한다.**
`Stage-2A (합성 축소 노심)`을 먼저 돌려 **G2-a를 싸게 반증 가능하게** 만들고,
`Stage-2B (실 OPR1000)`은 자산 확보 시점에 착수한다. **2A가 실패하면 2B는 하지 않는다** —
합성 노심에서 전이하지 않는 표현이 실제 다른 플랜트에서 전이할 이유가 없다.
이것이 이 문서 전체에서 **비용 대비 반증력이 가장 높은 한 수**다.

| **G0-b** | **체크포인트 적재.** s1g 5멤버 `state_dict`를 재적합 네트에 로드해 동결 3,207행에서 `mu`/`map`/`log_sigma` 재현 | 상대오차 ≤ 1e-5 |
| **G0-c** | **재학습 동등성.** 신규 학습 앙상블이 동결면에서 s1g와 동등 | 여섯 ρ_iso 전부 \|Δ\| ≤ **0.018**; MAE는 s1f→s1g 단계 폭(예: cyclen 2.872→2.982) 이내 |

**반증 판독**
* **G0-a 실패** → 이것은 리팩터가 아니라 물리 변경이다. **즉시 중단**하고 어느 파생량이
  달라졌는지 특정한다. (이 프로그램의 "flag-off 바이트 동일성 계약" 규율 그대로.)
* **G0-b 실패, G0-a 통과** → gather/scatter 재배선 버그. 국지 문제.
* **G0-c만 실패** → **정보력 있는 무효.** 고정 241-슬롯 마스크가 마스크 일반 경로가
  담을 수 없는 무언가를 담고 있었다는 뜻이다 (예: 맵헤드의 고정 scatter가 학습된 위치
  프라이어로 작동). **이것이 인코더 경로 재고를 정당화하는 유일한 증거이며,
  그 전에는 GNN을 고려하지 않는다.**

### Stage 2 — 제2 노심 few-shot · **2A(합성 축소) → 2B(실 OPR1000)** 두 갈래

**§6.1 판정: OPR1000 MASTER 자산은 리포지토리에 없다.** 따라서 Stage-2를 쪼갠다.

#### Stage 2A — 합성 축소 노심 (선행, 싸고 반증력 최대)

`CoreGeometry`의 `row_lengths`를 잘라 **15×15급 가상 노심**을 만들고, **같은 ga80/paramA
연료·같은 `MAS_REF` 반사체**로 MASTER 덱을 합성한다. 자산 획득 대기 없이
**G2-a(제로샷 전이)의 인코더 층위 명제를 그대로 검사**한다. APR1400 패턴을 축소 사영해
엘리트 부모로 쓸 수 있으므로 §6.3의 "부모 0개" 문제도 완화된다.
**문서·프리레지·그림에 "합성"을 반드시 명시** — "OPR1000에서 된다"는 주장은 하지 않는다.
**2A가 실패하면 2B는 착수하지 않는다.**

#### Stage 2B — 실 OPR1000 (자산 확보 후)

**선행조건** — §6.4 표의 항목 1·2 (노심 덱 + 집합체 XS). **v3 범위 밖의 자산 작업이다.**

**작업 (2A·2B 공통)**
1. `CoreGeometry.<plant>` 구성 + `coredeck` 플랜트 판 + `MAS_XSL` + 재시작 베이스.
2. `opmodel` 해당 플랜트 인스턴스 (§6.2, **자유 per-feed 인자 포함**) — **라벨 생산 전에 먼저 선다.**
3. 라벨 생산: 프로브 8 → 개통 **150–200**(부모 0 보정) → LRM 앵커 열당 3–5점.
4. **동결-미세조정** — 이 프로그램의 **표준 레시피**를 그대로 쓴다:
   `--init-from <champion> --freeze-trunk-cyclen` (`al_retrain.py`).
   근거: 2026-07-24에 4연속 게이트 실패 후 이 레시피가 **첫 통과**를 냈고
   (cyclen drop 0.013≈0, 경계 F_r ρ 0.29→0.322, node_peak ρ 0.617→0.783),
   그 후 AL 재학습 표준이 되었다. **새 플랜트는 정확히 "트렁크 표현을 지키고 크기 민감
   헤드만 적응시켜야 하는" 상황이다.**

**N 라벨 수 — 추정이 아니라 곡선으로 읽는다.** 사전등록 시점에 값을 고정하지 말고
**N = 0 / 40 / 80 / 120 / 240 / 360에서 홀드아웃 ρ_iso 곡선을 그린다.** 근거:
이 프로그램은 학습곡선을 이미 측정했다 (λ ∝ n^(−0.21..0.38)), 그리고 스플릿 arm에서
1,413행 증분이 엘리트밴드 F_r MAE 0.856→0.594를 냈다.

**게이트 (사전등록)**

| ID | 검사 | 통과 기준 |
|---|---|---|
| **G2-a** | **제로샷 전이 (핵심 명제)** | 신 노심 라벨 **0개**로 서빙했을 때 홀드아웃 셀내 ρ(f_r) ≥ **0.60** |
| **G2-b** | few-shot 효율 | N=120에서, 같은 120행으로 **from-scratch** 학습한 대조군보다 ρ_iso 우세 (전 지표) |

  **연료 테이블만 공유**한다 (그것만으로도 격자체인 재사용 이득은 유지된다).
  이 판독을 사전등록에 반드시 적어라 — 나중에 "부분적으로 됐다"로 흐리지 않기 위해.

* **G2-a 통과** → §2.6의 feed-축 전이가 **크기 축으로 확장됨이 확인**. v3의 핵심 베팅 성립.
* **G2-c 실패** → 부정적 전이. 커리큘럼 셀 4 판정의 선례가 있다(불가피한 부정적 전이는
  기록하고 셀을 종결). 플랜트별 헤드 분기를 검토한다.

## 9. 만들지 말 것 (ponytail)

1. **GNN 인코더.** §4. 트렁크가 이미 크기 불가지이고, 수용영역이 이미 전역이고, 기하가 이미
   단일 파생 원천이고, 파라미터가 보존된다. **트리거만 등록** (육각격자/이종피치 노형 진입).
   Stage-0 G0-c가 실패하기 전에는 설계도 프로토타입도 만들지 않는다.
2. **파라미터 확대.** 스케일링 판정이 무릎점을 찍었다 (10.4M×5, 확대·축소·앙상블10 전부 기각).
   크기 불가지는 **인덱싱 문제**다. "크기 일반화를 위해 용량을 늘린다"는 제안은 사전 기각.
3. **핵종 인벤토리 39핵종 채널화.** §3.4. 원천은 있지만 k(BU)+형상+XS가 이미 그 사영이고,
   v6c face-ADF 실패가 "원천에 정보가 더 있다 ≠ 채널이 도움된다"를 실측했다.
   **원천이 있다는 사실만 기록**한다.
4. **62점 k곡선 전체 채널화.** §3.1. 곡선 압축오차(1,402 pcm) < 연소도 배치오차(2,801 pcm).
   더 작은 오차원을 쫓는 일로 이미 정량 판정났다. 62점 곡선은 **LRM 입력**으로만 쓴다.
5. **MTC/FTC/SDM을 예측 타깃으로 승격.** §3.3. 하네스는 있고 **라벨이 0개**다.
   라벨 없이 헤드를 다는 것이 정확히 v6c의 실패 모드다. 먼저 캠페인 후검증에서
   top-5 × 2콜 = 10 %/캠페인으로 라벨을 쌓아라.
6. **축방향 자유도를 APR1400/OPR1000 v3에 넣기.** 사용자 지시 2026-07-25로 **이미 금지**.
   i-SMR 전용. v3에서는 `CoreGeometry`에 **필드 자리만** 만든다.
7. **새 플랜트 전용 from-scratch 모델.** Stage-2의 G2-a/G2-b가 전이를 반증하기 전에는
   만들지 마라. 반증되면 그때가 **정당한** 시점이고, 그때는 대조군으로서 이미 존재한다.
8. **`autoeng` 실행 골격 재작성.** 셀 순차 루프·프리레지 자동화·append-only 상태로그·
   3개 휴먼 게이트는 그대로 둔다. 플랜트 축은 `[[targets]]`의 키 하나여야 한다.
9. **크기 불가지화와 동시에 채널을 추가하는 것.** Stage-0과 Stage-1을 합치지 마라.
   합치면 G0-c가 무엇을 측정하는지 알 수 없게 되고, 재적합의 무해성 증명이 사라진다.
   이 프로그램의 arm 규율(한 번에 한 메커니즘)이 그대로 적용된다.
10. **`vendor/masterrl` 스냅샷을 리팩터링하는 것.** 벤더는 수화된 스냅샷이고 상류가
    드리프트한다. `CoreGeometry`는 벤더를 **감싸야지** 벤더를 다시 쓰면 안 된다
    (`domain.ROW_LENGTHS`에 기본 인자를 주는 최소 변경까지만).
11. **동결 36셀 평가면으로 v3의 *이득*을 주장하려는 것.** 그 면은 다섯 세대 연속으로
    바닥을 못 넘었다(최대 +0.0023). **비회귀 계측기이지 개선 계측기가 아니다** (§8 박스).
    이득 주장은 그물망 실현확인 셀 수 또는 캠페인 프런티어로만 한다.
    반대로 **평평하다고 실패로 읽는 것도 금지** — s1g가 이미 그 오독의 선례를 남겼다.
12. **해석적 `2/(n+1)` LRM을 새 플랜트 백본으로 쓰는 것.** dbx 6,113 코어가 반증했다
    (rms 4.061 → feed 보정 2.364). **자유 per-feed 인자를 반드시 실어라** (§6.2).
    그리고 `bu_k1`을 연료 기술자로 써라 — 농축도보다 9 % 낫다.
13. **`ceil_cyclen`을 상한으로 쓰는 것.** e5.1–5.5 발자국 안 30셀 중 **24셀에서
    실측 코어가 그것을 넘는다**. **e6.0 행은 격리 대상** (그물망 자체의 불연속).

## 10. 미결 — 사용자 결정이 필요한 항목

1. **v3 범위 확정** — "APR1400 + OPR1000 반경방향"으로 자르고 i-SMR을 후속 프로그램으로
   분리하는 것에 동의하는가? (§7). **이 결정이 나머지 전부의 크기를 정한다.**
2. **OPR1000 자산** — §6.1/6.4의 판정에 따라, 부재 자산(MASTER 모델 / XS 라이브러리 /
   재시작 베이스)을 조직 내부에서 확보할 경로가 있는가? 없다면 Stage-2는
   "OPR1000"이 아니라 **"합성 축소 노심"**(APR1400 마스크를 잘라 만든 가상 15×15)으로
   대체 가능하다 — 물리적으로는 약하지만 **G2-a의 인코더 층위 명제는 그대로 검사된다.**
   (비용 대폭 감소, 정직성은 "합성"이라고 명시하면 유지됨.)
3. **Stage-1 arm 예산** — A/B 1사이클로 다섯 항목(경계·좌표·전역·M²·RHO_LEAK)을 묶을지,
   메커니즘별로 쪼갤지. 이 프로그램의 규율은 후자이나 사이클이 5배가 된다.
   **권고: 경계+좌표+전역을 한 arm(기하 블록), M²+RHO_LEAK을 한 arm(프라이어 블록)** — 2 arm.
4. **MTC/SDM 라벨 축적 개시** — 캠페인당 top-5 후검증(10콜, +10 %)을 상시로 켤 것인가.
5. **`autoeng`의 플랜트 축** — v3 모델이 준비되면 `autoeng.toml`에 `plant` 키를 추가하고
   함대 규칙을 플랜트별로 나눌 것인가.
6. **계획 문서의 경로** (§2.8) — `lpopt/` 코드가 ~50곳에서 "plan sec. X.Y"를 인용하는 그
   문서를 이 머신에서 찾지 못했다. §12.4/§12.5는 코드 인용에서 **재구성**한 것이다.
   원본 경로를 알려주면 이 문서의 해당 절을 원문으로 교체한다. (재구성이 틀렸을 위험은
   낮지만 — `featurize.py`가 §12.4를 축어 인용하고 `config.py`가 §12.5 독스트링을
   그대로 담고 있다 — **재구성이라는 사실 자체는 기록되어야 한다.**)
7. **`REFLECTOR_CHAIN.md` §3의 negative evidence 정정** (§6.1 부수 발견) — 그 문서는
   "APR1400 반사체 DeCART2D/PROLOG 입력이 저장소 어디에도 없다(0건)"고 기록했으나,
   `99_Archive/SAMPLE/DeCART2D/Radial_reflector/dec_APR_radial.inp` +
   `pro_APR_radial.inp`(**`REFLDATA` 포함**)가 실재한다.
   벤치마크 세트 문서의 정정을 등록할 것인가.
8. **`config/fuel_types_dbx_extracted.yaml` 병합** (v3와 별개지만 선행이 유리) —
   `dbx_frontier_note` §3: **286 프런티어 셀 중 83개가 유효 ga80 행 0개**이고,
   `E5_E6`(56 코어) / `J7_J8`(416 코어)는 **타입이 `fuel_types.parquet`에 없어서** 0이다.
   40타입(신규 4) 병합은 **집합체-출력 표현의 커버리지를 넓히는 가장 싼 조치**이며
   v3의 전이 실험에 쓸 수 있는 타입 다양성을 늘린다.
